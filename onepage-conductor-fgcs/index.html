01
Pipeline 气泡从何而来? Structural & Dynamic Variance · Section 2

流水线并行把 LLM 切成 N 个 stage 串行跑,但每个 microbatch 的真实执行时间 不是常数。最新生产 trace 显示,约 42.5% 的训练任务至少经历一次 10% 减速 (Lin et al. 2025, OSDI)。Straggler 让最快设备等最慢设备,空闲时间 = Tπ(D),t - Ti,t。

📊 四大方差源:
① 结构层: 端到端 stage 异构,均匀切层仍有 3–7% 执行时间差 (embedding / logits);
② 微批次层: Attention 是 O(T²d),同 GPU 跑 8K 序列要 3.616 ms,跑 8×1K 只要 0.569 ms,差 6.3×;
③ F/B/W 反对称: 前向/反向/权重更新计算量天然不等;
④ 系统层: 网络抖动 + 内核方差,违反 1F1B 的"均匀时间"假设。
图 1 · 静态 1F1B 调度下,Stage 2 慢 → Stage 0/1/3 全员等 (气泡 ≈ 25%)
02
粗粒度: 用 RL 替换 ILP 做全局调度 Macro RL Scheduler · Section 4

静态 ILP 找最优计划要 指数级时间,且对扰动脆弱。Conductor 把流水线调度形式化为 MDP,让强化学习 agent 在毫秒级给出新计划,响应网络抖动 / 节点抢占等运行时事件。

State: st = (stage 状态 3D) + (microbatch 状态 3M) + (全局 4D) + (候选事件 6·3DM)
Action: 选下一个执行的操作槽 (有界动作空间,处理组合爆炸)
Reward: rt = − (执行时长 + 气泡惩罚 + 内存违规惩罚)
🎯 两阶段训练 (解决动作空间爆炸):
Stage 1: Behavioral Cloning 从强启发式 (Zero Bubble) 蒸馏,bootstrap 出合理策略;
Stage 2: PPO + Domain Randomization 微调,加 0–30% 噪声 + Pareto 拖尾 + 突发拥塞,确保对系统抖动鲁棒。

💡 调度开销极小: 单次策略推理 0.086–0.093 ms (P99 < 0.17 ms),每次 run 96 次决策共 ~9 ms,相对总训练时间可忽略。

03
细粒度: 把算子从慢设备搬到快设备 Computation Migration · Section 5

RL 给的是宏观执行顺序,但 slot 内的 variance 仍残留。Conductor 在每个时间槽内,实时 profiling 各设备耗时,把慢设备的 Attention 头 或 MLP 切片 卸载到快设备,把通信开销藏在本地计算的后面。

对称配对 (Algorithm 2): 把设备按时长排序,快慢配对 (k, N−k+1),
目标迁移量 Ttransfer(k),P = (T慢 − T快) / 2
F/B pass: 先迁整数个 attention head,残余用 MLP 分数 α 补足
W pass: 没有 attention,只切 MLP (α ≤ 1)
图 2 · 对称配对 + 算子切分,把快慢设备拉到同一完成时间
🔒 Stall-free 通信条件 (Eq. 11): α ≤ (Tslow-fwd − Csend_act − Crecv) / (2·Tslow-fwd + Csend_weights)
A100 + 100 Gb/s 网络下 αmax ≈ 0.307,即最多 30.7% MLP 可无阻塞迁移。通信必须能藏在算力后面,否则得不偿失。

三个常见误区Three Things to Watch Out For

✗
"ILP 解一次就够,直接用静态计划"
ILP 指数复杂度,且对运行时扰动极脆弱 — 一旦某 microbatch 慢 10%,整个计划崩盘。RL 推理 0.09 ms,实时性完全不是问题。
✗
"DualPipe / DynMo 已经够好了,不需要动态"
它们是半动态,优化特定 workload (如 MoE),在通用 stochastic 条件下仍有大块气泡。Conductor 在重尾 + 突发拥塞 + 异构容量压测下都把气泡压到 ~1%。
✗
"RL 和 Migration 是两套独立方案,二选一"
它们是互补的:RL 解决跨 stage 宏观执行顺序 (毫秒-秒级),Migration 解决单 slot 内 微观 variance (微秒级)。Table 6 显示两者叠加比单独用 Migration 还快 6.2% (242.73 vs 258.80)。

这一页先记住 · TL;DR

What to Take Away
问题
流水线气泡 = Straggler 拖垮, 静态调度在 stochastic 硬件上既慢又脆。
方案
两层解耦: RL 粗调度 (MDP+BC+PPO) + 算子迁移 (Attention head + MLP 切分)。
结果
Megatron-LM 5–14% 吞吐提升; 仿真 0.79% 残余气泡率, 跨 0–30% 噪声稳定。
🚀 Conductor = 抗 straggler 的 多粒度动态控制 — 粗粒度 (RL 重排执行序) + 细粒度 (算子切分迁移) 双管齐下, 把流水线气泡从 25% 压到 < 1%。
