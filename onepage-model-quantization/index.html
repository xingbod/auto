核心思想:用更低精度存,牺牲极小精度换 4 大收益

LOWER PRECISION, BIG WINS

训练用 FP32 (4 字节/参数), 推理可以压到 INT8 (1 字节) 甚至 INT4 (0.5 字节) —— 模型小 4-8 倍, 速度 2-4 倍。

FP32 训练精度
  • 位宽: 32 bit 浮点
  • 大小: 7B 模型 ≈ 28 GB
  • 用途: 训练 / 高精度推理
  • 代表: 默认 LLM 训练
INT4 量化后
  • 位宽: 4 bit 整数
  • 大小: 7B 模型 ≈ 3.5 GB
  • 用途: 边缘 / 消费级 GPU
  • 代表: GPTQ · AWQ · GGUF Q4

6 大位宽对比:精度 / 大小 / 损失 / 场景

BIT-WIDTH COMPARISON

选哪个位宽, 关键看"任务精度要求 + 硬件能力"。下表是 7B 模型典型参考:

位宽 大小 (7B) 精度损失 吞吐 典型场景
FP32 28 GB 0% (基线) 1x 训练 / 服务器高精度
FP16 14 GB < 0.1% 2x GPU 训练 / 推理标准
BF16 14 GB < 0.1% 2x 大模型训练 (稳定)
INT8 7 GB ~0.5% 3-4x CPU/GPU 通用推理

05

新手最常踩的 4 个坑

COMMON PITFALLS
✗
"量化一定掉精度" 👉 INT8 通常 < 0.5% 损失, 好的 INT4 也 < 2%。先用 PTQ 校准, 大部分场景不需 QAT。
✗
"INT4 一定比 INT8 好" 👉 越激进越掉精。敏感任务 (代码 / 数学) 优先 INT8, 创意任务 (对话) 才用 INT4。
✗
"所有层同等量化" 👉 首/尾层 + attention 敏感。用 mixed-precision 跳过关键层, 或 AWQ/SmoothQuant 自动保护。
✗
"PTQ 不需要校准数据" 👉 校准数据直接决定量化质量。要代表业务场景的几百~几千样本, 不能用 ImageNet 校准 LLM。
这一页先记住 · TL;DR
  • WHAT降位宽 (FP32→INT8/INT4), 4-8x 压缩, 2-4x 加速
  • HOWPTQ 快 / QAT 准, 选 AWQ/GPTQ/QLoRA/GGUF
  • KEY校准数据 + 敏感层保护 + outlier 处理
一句话总结:模型量化 = FP32 → INT8/INT4 压缩 + 加速, PTQ (快) vs QAT (准) 二选一, 主流用 GPTQ/AWQ/QLoRA/GGUF, 校准数据和 outlier 是关键。
