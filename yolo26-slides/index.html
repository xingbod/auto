本课要回答的 4 个问题

Learning objectives

❶ 是什么

YOLO26 是 Ultralytics 2026 年发布的端到端实时视觉模型家族,在 5 个尺度(n/s/m/l/x)上同时支持检测、实例分割、语义分割、姿态估计、定向检测、分类 6 大任务。

❷ 为什么重要

它抛弃了 NMS 后处理(NMS-Free)和 DFL 复杂回归头(DFL-Free),CPU ONNX 比 YOLO11n 快 43%,是 YOLO 系列第一次"原生端到端"。

❸ 长什么样

经典 C3k2 主干 + SPPF + C2PSA + FPN/PAN + 双头检测结构,但把 DFL 头换成了 one-to-one + one-to-many 双头。

❹ 怎么训练

3 个新配方:MuSGD 混合优化器、Progressive Loss 渐进监督、STAL 小目标标签保证。

一句话总结: YOLO26 = YOLO11 架构 + DFL-Free 双头 + MuSGD/PL/STAL 训练三件套,目标是把"又快又小"推到新极限。

YOLO26 的定位: 不是又一次"刷 mAP",而是把 推理流程彻底简化(扔掉 NMS、扔掉 DFL),同时训练侧搬来 LLM 圈的 Muon 优化器,做到"训推两端都更轻"。

YOLO26 的 4 大设计理念

把 4 个长期痛点一次性解决

🎯 设计 1 · 原生 NMS-Free 推理

用 one-to-one 双头(训练时辅助 one-to-many),默认推理时直接出框,不再需要 NMS 后处理。部署简单,延迟稳定。

🪶 设计 2 · 去掉 DFL 的轻量回归头

扔掉 Distribution Focal Loss(原本需要额外的 softmax + 积分),保留无约束回归范围。检测头复杂度显著降低,导出更简单。

🧪 设计 3 · 训练三件套

MuSGD Muon+SGD 混合优化器(从 LLM 借鉴);Progressive Loss 把监督向推理头倾斜;STAL 保证小目标一定有正标签。

🧰 设计 4 · 任务头统一

一条主干 + 5 个任务头:Detection / Seg / SemSeg / Pose / OBB / Cls,共享 5 个尺度(n/s/m/l/x),单条 pipeline。

🔹 Backbone(特征提取)

4 段下采样 + C3k2 模块,从 640→320→160→80→40→20 共 5 级;最后接 SPPF (5/9/13 感受野) 和 C2PSA (PSA 注意力)。输出 P3/P4/P5 三个尺度。

🔹 Neck(多尺度融合)

FPN↑(自顶向下) + PAN↓(自底向上) 经典 U 形,带 Concat 拼接和 C3k2 融合。让浅层有"语义",深层有"细节"。

🔸 Head(双头检测)

每个尺度一个 Detect 模块:
· one-to-one: 一对一标签,推理时直接出最终框 → NMS-Free
· one-to-many: 一对多标签,只在训练时跑,提供更密的监督

🔸 输入输出

输入:任意尺寸图像(默认 640×640)
输出:boxes(xyxy/xywh + class + conf),按任务不同附加 mask/keypoint/angle/cls

🧩 关键改动: 沿用 YOLO11 的 C3k2/SPPF/C2PSA 骨架,只在 Head 上做革命(双头 + DFL-Free)。Backbone + Neck 几乎没动 → 迁移老经验零成本。

⊕ Concat 拼接 · ↑/↓ 上下采样 · 详细 block 级图见 yolo26s-arch/yolo26s-det-architecture.html(YOLO26s 详细版)

Backbone 详解: C3k2 + SPPF + C2PSA

和 YOLO11 同款骨架,沿用成熟的轻量化设计

🔹 Stem: 两层 Conv 下采样

把 640×640 两次 /2 下采样到 P2/4 (40×40×128)。纯卷积,不丢语义。

🔹 主干: 4 段 C3k2

C3k2 是 YOLO11 引入的"小型跨阶段部分块"——把 C2f 的 Bottleneck 换成更小的 k=3 卷积。计算量更小,精度持平。最后一段打开 csp=True 增加跨分支。

🔹 SPPF: 空间金字塔池化

3 个 5×5 串行 MaxPool 拼起来,等价于 5/9/13 三种感受野。让 5×5 特征图同时看到大、中、小上下文。

🔹 C2PSA: PSA 注意力

C2f 里塞一个 PSA (Polarized Self-Attention) 块,只增加很少的 FLOPs,换来位置敏感的特征加权。

通俗类比: Backbone = 眼睛 + 初级视觉皮层。Stem 是"看清轮廓",C3k2 是"识别局部图案",SPPF 是"理解周围语境",C2PSA 是"决定哪里值得多看两眼"。
📐 输出 4 个尺度

最终产生 P3/8, P4/16, P5/32 三层送给 Neck,YOLO26-p6.yaml 还可选 P6/64,YOLO26-p2.yaml 选 P2/4(给小目标场景)。

🧩 模块家族

YOLO26 沿用 Ultralytics 的"积木式"设计:CBS (Conv-BN-SiLU) → C3k2 → SPPF → C2PSA,这些积木在不同 YOLO 版本里被反复组合。

Neck + Head: FPN↑ + PAN↓ + 双头

多尺度融合 + 原生端到端检测

🔸 FPN 自顶向下 (Top-Down)

把 P5 上采样,与 P4 Concat,再 C3k2;再上采样与 P3 Concat。让浅层获得更强的语义信息(小目标也"知道自己在哪类东西里")。

🔸 PAN 自底向上 (Bottom-Up)

再下采样回 P4/P5,补一次 Concat。让深层的定位细节回流到浅层。FPN + PAN = 经典"U 形融合"。

🔸 三路 Detect 头

每路都是同一个 Detect 模块,但在 3 个尺度上分别负责小/中/大目标。

双头(Dual-Head)新设计: 训练时每个 Detect 跑两个分支——one-to-one 一对一匹配(出最终框)+ one-to-many 一对多匹配(更密的监督);推理时只跑 one-to-one,直接出框,无需 NMS。
🆚 跟 YOLOv8 的区别

v8 训练用 one-to-many,推理要 NMS 去重;YOLO26 训练已经学到"一对一也能准",推理时省掉 NMS 一整个步骤。

📏 输出 head 维度

reg_max = 1(DFL 砍掉,直接回归 xywh);分类仍按 nc = 类别数;YOLO26n 共 ~260 层,2.57M 参数。

创新 1: DFL-Free + NMS-Free 双头

把检测头"减负"到极致

🧬 什么是 DFL?为什么要砍?

DFL (Distribution Focal Loss) 把 bbox 边界回归成"离散概率分布"(比如 16 个 bin),推理时再积分出精确值。

  • ✅ 优点:回归更准、范围灵活
  • ❌ 缺点:head 多一层 softmax + 积分,导出复杂、CPU 慢

YOLO26 改用直接回归 (xywh) + 无约束范围。轻 43% CPU 推理速度就是这么来的。

🚫 什么是 NMS?为什么能砍?

NMS (Non-Maximum Suppression) 是后处理:把同目标的多框用 IoU 去重。

  • ❌ 痛点:超参数敏感(阈值/类别)、延迟与目标数线性相关、难部署
YOLO26 的解法: 训练时同时跑 one-to-one(一对一)+ one-to-many(一对多),one-to-one 头学到"我直接出最准的那一框",推理时只用它 → 彻底跳过 NMS。
传统 YOLO 推理流程 图像 → Backbone → Neck → Detect 头 ↓ 100+ 个候选框 + 类别分 ↓ NMS 去重 (CPU 慢、参数敏感) ↓ 最终检测框 (1-50 个) ↓ ≈ 1-10 ms 后处理 ↓ 输出 ─────────────── YOLO26 推理流程 图像 → Backbone → Neck → Detect 头 ↓ (one-to-one) 直接出最终框 (无需 NMS) ↓ 输出

创新 2: MuSGD 优化器

把 LLM 圈的 Muon "移植"到视觉模型

🧠 传统视觉用 SGD/AdamW

YOLO 系列长期用 SGD(momentum) 或 AdamW。SGD 稳但慢,AdamW 快但泛化有时差。

🚀 Muon 是什么?

Muon (Momentum Orthogonalized by Newton-Schulz) 是 2024 年 LLM 训练新出的优化器:对动量做正交化(Newton-Schulz 迭代),让更新方向"互相正交",收敛更快、loss 更低。

🔀 MuSGD = Muon + SGD 混合

YOLO26 不直接全用 Muon,而是:对大部分参数用 Muon(卷积、注意力权重),对 head/BN/bias 仍用 SGD。两边互补,既享受 Muon 的快,又保持 SGD 的稳。

为什么值得借鉴? LLM 训练积累的优化器经验正在反哺视觉模型。MuSGD 是 YOLO26 把"训练配方现代化"的关键一步。
📚 类比

SGD 像"老司机稳稳开",Muon 像"赛车手在弯道正交加速",MuSGD 是"高速 + 安全"组合。

⚙️ 实现细节

每个 step:sgd_param ← μ·sgd_param + ∇L,然后 muon_param ← NewtonSchulz(muon_momentum),最终 w ← w - lr·update。这是真正能跑的工程化版本。

创新 3: Progressive Loss + STAL

把"训练-推理 gap"和小目标漏检一起治了

📈 Progressive Loss (渐进式损失)

YOLO26 有 one-to-one (推理头) 和 one-to-many (训练头) 两个头。训练初期更依赖 one-to-many 的密监督;训练后期逐渐把权重 λ(t) 推向 one-to-one,让它和推理时一致。

这样:训练分布 ≈ 推理分布,避免"训得好但部署拉胯"。

🎯 STAL (Small-Target Aware Label assignment)

小目标(像素少)在标签分配时容易被当作"无目标"。STAL:强制每个 ground-truth 至少有一个 anchor 被分到正标签,且提高小目标权重。

组合效果: Progressive Loss 解决"训推不一致"问题;STAL 解决"小目标饿死"问题。两者合起来,YOLO26 在 COCO 小目标 / 中目标子集上提升明显。

同一个 YOLO26 主干,通过切换 head 支持 6 类视觉任务

统一哲学: 一条 backbone + 5 个尺度 (n/s/m/l/x) + 6 个 head,改任务只需改最后那个 head 和 loss。开源生态友好,工程落地快。

总结 & 参考文献

一页带走 + 论文 / 代码 / 文档

✅ YOLO26 核心要点

  • 4 大设计: NMS-Free 双头 / DFL-Free 轻量头 / MuSGD+PL+STAL 训练 / 6 任务统一
  • 架构: C3k2 + SPPF + C2PSA + FPN↑ + PAN↓ + 双 Detect
  • 性能: 40.9–57.5 mAP @ 1.7–11.8 ms T4,CPU ONNX 较 YOLO11n +43%
  • 规模: 5 个尺度 (n/s/m/l/x) + 6 大任务 (Det/Seg/SemSeg/Pose/OBB/Cls)
  • 开放词汇: YOLOE-26 文本/视觉 prompt,LVIS minival 40.6 AP
怎么选? 边缘/移动 → n 或 s;服务器实时 → m/l;研究/极致精度 → x;小目标 → p2;大图/遥感 → p6。
