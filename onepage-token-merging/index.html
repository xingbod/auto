01为什么需要 Token Merging?
Motivation

ViT 对图像切成 N 个 patch token,自注意力计算量随 N 平方增长。但一张图里大量 patch 是冗余的(如背景天空、重复纹理),它们对最终预测贡献极小,却消耗同等的注意力算力。

已有方案:Token Pruning(裁剪)直接丢弃"不重要"的 token → 信息不可逆丢失,且需要训练特定模块决定丢哪些。ToMe 的洞察:与其丢,不如合 —— 把相似 token 取平均合成一个,既减数量又保留信息。

核心思路对比 Pruning:  x1, x2, x3 → 丢弃 x2 → x1, x3   (信息永久丢失!)
Merging:  x1, x2, x3 → 合并 x1⊕x2 → x12, x3  (信息被平均保留)
02核心算法: 双分软匹配 + 贪心合并
Bipartite Soft Matching

ToMe 在每个 Transformer Block 的自注意力之前插入一个合并步骤。关键在于:如何找出"最相似"的 token 对?

步骤操作细节
1. 分集合
Split		 把当前 t 个 token 沿序列维度交替分成 A、B 两个等大集合 (奇数位→A, 偶数位→B) 两集合无交集, 保证合并只在跨集合间发生, 避免链式合并
2. 算相似度
Similarity		 用注意力 Key 矩阵 K, 计算 A 中每个 token 和 B 中所有 token 的余弦相似度 score(i,j) = ki · kj, 复用已有的注意力投影权重
3. 双分匹配
Match		 对相似度矩阵做贪心双向匹配, 找到 A↔B 之间最相似的 r 对 token 等价于在二分图上求最小权匹配, 一次匹配只配对一次, 不重复合并
4. 合并
Merge		 将每对匹配的两个 token 取平均合成一个新 token (按 (Hadamard) 乘上聚类大小归一化) xmerged = (xa + xb) / 2, 维度不变
5. 继续
Forward		 合并后的 t-r 个 token 进入正常 Self-Attention + MLP → 下一层重复 无缝插入, 不修改原始架构权重
Bipartite Matching 核心逻辑 Input:  tokens X ∈ Rt×d,  keys K = X·WK
Split A, B ⊂ X  (|A| ≈ |B| ≈ t/2)
S(i,j) = cos( KA,i, KB,j )   ← 相似度矩阵 S ∈ R(t/2)×(t/2)
M =Hungarian(S)top-r  ← 贪心选 r 对最相似的配对
X' = merge(X, M)     |X'| = t - r
03三个关键设计选择
Key Design Choices
设计点ToMe 的选择为什么不这样做 (替代方案的问题)
训练无关
Training-Free		 不修改任何模型权重, 不需任何额外训练, 像一个即插即用的前向传播 patch 替代方案 (DynamicViT / EViT) 需要训练 预测器 决定丢哪些 token, 切换任务就要重训
双向匹配
Bipartite		 将 token 交替分 A/B 两集, 跨集合做一对一匹配 → 每次最多合成 t/2 对 直接贪心会出现链式: 一个 token 被合并到 A 后还说"和 B 也相似"再被合一次 → 团块化失真
密度保留
Density		 合并后保留所有但减数量: x1+x2→x12, 不丢信息只是均匀重新平均 Pruning 直接删 token → 不可逆丢失, 且需额外训练预测器, 越大比例越脆
为什么交替分配 A/B 而不是按空间分? 交替分配保证: 每个token都能在另一半集合中找到潜在匹配对象
如果按空间分(如左侧 vs 右侧) 跨空间合并会破坏局部性, 但交替分配每一对都来自不同空间位置, 天然支持跨区域融合

⚠ Common Pitfalls · 4 个理解误区
✗
ToMe 需要重新训练模型 在 ViT 上加合并层就要 fine-tune
👉 ToMe 是 training-free 的: 不修改权重, 不需要数据, 像一个前向传播操作直接插入即可用
✗
合并 = 裁剪, 都是删 token 反正都减少 token 数, 效果差不多
👉 合并 = 两个 token → 取平均 → 1 个等维新 token (信息被差分式保留); 裁剪 = 直接丢弃 token (信息永久丢失)
✗
随便取两个相似 token 合并就行 直接对全部 token 做全局贪心配对
👉 必须用双向匹配: 先分奇偶 A/B 两集, 再跨集做一对一匹配, 否则会出现链式合并、一个 token 被反复合并
✗
合并越多越好, 压缩率越高越好 把 r 设到最大, 反正不掉点
👉 r (每层合并数) 越大, 精度下降越明显 (ViT-B/16 上 r=16 可控, r=32+ 开始明显损失); 建议开始用 r=8
★ TL;DR · 3 个要点先抓牢
What

在每个 Transformer Block 前用双向软匹配从 t 个 token 中合并 r 个相似 token (取平均), 不丢信息, 不改权重

How

交替分 A/B 两集 → 用注意力 Key 算余弦相似度 → 贪心匹配 top-r 对 → 每对取平均合并 → t-r 个 token 继续

Result

对 ViT-B/16 获 2× 加速, 仅损 ~0.3% top-1; 适用于分类/检测/分割/视频, 无需训练

Token Merging 让 ViT "不训练、不掉点、插即用": 通过双向匹配找到最相似的 token 对并取平均合并,
每层减 r 个 token 实现最高 2× 加速, 信息因为"合"而非"丢"而得以保留
