核心思想：把"加锁的手"伸进保险箱

COMPUTE ON CIPHERTEXT

传统加密：想算数据 → 必须先解密 → 计算方看到明文。
同态加密：不解密也能算，结果解密后 = 在明文上算的结果。

E(m1) + E(m2) = E(m1 + m2)
同态性质: 在密文上做运算 = 在明文上做同一运算后再加密

03

关键技术：噪声管理 (Noise Budget)

NOISE BUDGET & BOOTSTRAPPING

同态加密最大的"工程难题"是 噪声: 每次乘法都加噪, 噪声到顶 → 解密失败。

核心矛盾: 想算的电路越深, 参数就得越大, 性能越差。 关系: 深度 ↑ → 参数 ↑ → 密文膨胀 ↑ → 速度 ↓

Bootstrapping (Gentry 2009 突破): 把"已经快爆掉"的密文,再同态地跑一遍解密电路, 得到一个"满血复活"的新密文。 代价: 单次 bootstrap 极慢, 是 FHE 的主要性能瓶颈。
04

典型应用：FHE 在哪能用、怎么用

APPLICATIONS & TOOLCHAIN

FHE 还没有"杀手级应用", 但 4 类场景在快速成熟:

🧠 隐私 ML
在加密数据上训练/推理模型。CKKS 特别适合 (浮点近似)。 场景: 医疗 AI / 金融风控 / 跨机构联邦。
☁️ 安全外包
把敏感数据加密后丢给云, 云算完返回密文, 用户本地解密。 场景: 加密数据库查询、机密基因分析。
⛓️ 机密区块链
智能合约在加密状态下执行, 链上节点看不到交易明文。 场景: 机密 ERC20 / 链上拍卖 / 隐私 DeFi。
🗳️ 隐私协议
电子投票 / 隐私拍卖 / 私有集合求交 (PSI)。 经典场景: 验证某人是否在集合里, 但不暴露集合内容。

05

新手最常踩的 4 个坑

COMMON PITFALLS
✗
"FHE 已经成熟, 可以随便用" 👉 FHE 比明文慢 1000x–10000x。先确认有没有更便宜的方案(MPC / TEE / DP), 别一上来就上 FHE。
✗
"同态加密 = 零知识证明" 👉 HE 是"在密文上算", ZKP 是"证明我知道"。前者保护数据, 后者证明陈述, 用途完全不同。
✗
"方案选错, CKKS 哪里都能用" 👉 CKKS 只能算近似值, 加密金额、投票计数要精确时用 BFV/BGV;算 ML 推理用 CKKS。
✗
"数据加密了 = 绝对安全" 👉 密钥在客户端, 客户端被攻破 = 全盘崩溃。HE 只保护传输和计算, 不替代密钥管理和访问控制。
