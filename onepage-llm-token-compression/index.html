6 大类方法:在 LLM 不同位置做减法

SIX CATEGORIES

按"在哪里减"分 6 类: 输入层、注意力层、记忆层, 越靠后越底层:

1 ✂️ Token 剪枝 PRUNING
直接丢掉不重要的 token, 留下任务相关的。
👉 位置: 输入层 / 输出层
2 🔗 Token 合并 MERGING
把相似 token 合并成一个, 减少 token 数。
👉 位置: 中间层
3 📦 提示压缩 PROMPT COMPRESSION
送 LLM 之前先用小模型打分, 删掉无信息 token。
👉 位置: 送入 LLM 之前
4 📝 上下文摘要 SUMMARIZATION
递归总结历史对话 / 长文档, 用摘要代替原文。
👉 位置: 记忆 / 长历史
5 🗃️ KV 缓存压缩 KV CACHE
注意力层 KV cache 逐层/逐头驱逐不重要项。
👉 位置: 注意力层
6 🌐 稀疏注意力 SPARSE ATTN
不计算所有 attention pair, 只看"重要"的。
👉 位置: 注意力层 (架构层)

新手最常踩的 4 个坑

COMMON PITFALLS
✗
"Token 压缩 = 无损" 👉 任何压缩都有损失。LLMLingua 20x 压缩通常掉 1-2%, 任务敏感时更明显。先评估再上。
✗
"KV 缓存压缩 = Token 压缩" 👉 两层不同: Token 压缩减输入, KV 压缩减中间状态。要叠加用, 单独都不够。
✗
"压缩率越高越好" 👉 压缩 ↔ 质量 反相关。INT4 20x 压缩 5% 损失没用, INT4 4x 1% 损失才实用。找 sweet spot。
✗
"提示压缩对所有 prompt 都好用" 👉 代码 / 数学 / 关键指令压缩易失效, 聊天 / 检索内容效果好。先按任务类型评估。
