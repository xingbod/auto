Chinchilla 法则 · 训练算力的最优配比
SCALING LAW · Compute-Optimal, not Size-Optimal

2022 年 DeepMind 的 Hoffmann 等人在《Chinchilla》论文里提出: 给定 训练算力预算 C, 模型参数量 N 和训练 token 数 D 应当按比例配比, 而不是"参数越多越好"。

Dopt ≈ 20 × N   →   Nopt ∝ C0.5, Dopt ∝ C0.5

直白讲: 训练 token 数 ≈ 参数量的 20 倍最划算。 一个 70B 模型应当用约 1.4T tokens 训练。 许多早期 LLaMA 之前的模型(GPT-3 175B 只训 300B tokens)严重欠训。

每条曲线 = 固定算力预算 C。曲线最低点 (★) 才是配比最优, 不是越靠右越好

02
涌现能力 · 临界规模才出现的"魔法"
EMERGENT ABILITIES · Phase Transition at Scale

部分能力在模型小的时候几乎为 0, 超过某个规模阈值后突然"涌现"。 这不是平滑的线性增长, 而是相变。

任务 / 能力涌现阈值 (约)表现
基础问答 / 翻译1 - 3B可用, 但简单
代码补全 (HumanEval pass@1)~13B从 0% 跳到 30%+
思维链推理 (CoT)~60B多步推理才稳定
工具使用 / Agent~70B自主调用 API 稳定
复杂数学 (MATH benchmark)~100B+竞赛题才上得去
多轮指令遵循 + 长上下文~300B+百万 token 级才有把握
⚠ 反例提醒: Schaeffer et al. 2023《Are Emergent Abilities a Mirage?》指出: 所谓"相变"很大程度是评估指标 (如 exact match) 选出来的, 改用连续指标后很多能力其实是平滑增长的。 所以"涌现阈值"是实用经验值, 不是物理学定律。
03
数据墙 · 公开高质量数据 2026 接近枯竭
DATA WALL · High-Quality Text Will Run Out by 2026

模型规模可以无限涨, 但高质量训练数据不会无限涨。 Common Crawl 累计 ~300B 网页, 清洗去重后能用的"教科书级"token 估计 ~15T, 按 2024-2026 头部模型训练速度 (每 2-3 个月翻倍), 高质量文本 2026 年底前见底。

两条曲线: 红色 = 头部模型训练 token 需求, 灰色 = 公开高质量数据存量, 即将交汇

⚠ PITFALLS · 4 个常见误区
这些错误思路, 会让你花错钱
✗
"参数越大越好" → 错。 数据-参数配比 (≈20:1) 才是关键。 GPT-3 175B 只用 300B tokens 是严重欠训, 同样的算力分给 70B + 1.4T tokens 反而更强 (Chinchilla 70B)。
✗
"小模型一定省钱" → 不一定。 QPS 高时, 7B × 100 万次调用 ≫ 70B × 1 万次调用。 推理时算力 (test-time compute) 是隐藏成本大头, 用 MoE 或投机解码才能破。
✗
"Chinchilla 法则永远适用" → 看场景。 训练期 vs 推理期 compute-optimal 是两套规则。 Snell et al. 2024 证明: 推理时让小模型多思考, 能反超训练时堆参数。o1 / R1 路线就是这条。
✗
"要训就训最大的" → 多数场景不是。 微调 7B + LoRA 经常胜过从零训 70B。 LoRA 只改 0.1%-1% 参数, 训练成本降 10-100×, 业务上常常够用 (LIMA 论文: 数据质量 > 规模)。
TL;DR · 这一页先记住
3 句话 + 1 个结论
No Silver Bullet
任务决定规模, 没有"足够大"的绝对值。 7B + 好 prompt + RAG 经常胜过 70B 单兵。
配比 > 规模
Chinchilla 法则: 训练 token : 参数 ≈ 20 : 1。 70B 模型应训 1.4T tokens 才算"喂饱"。
MoE 改写规则
总参 1T 但激活 32B, 看似巨大实则便宜。 Mixtral / DeepSeek-V3 / Qwen3-MoE 都是这条路线。
一句话结论: 模型规模没有"足够"这个绝对值 —— 它由 任务难度 × 数据配比 × 部署成本 共同决定。 算力最优配比 (Chinchilla) + 涌现阈值 (Emergent) + 性价比决策树 (Cost-Perf) 才是回答这个问题的三把钥匙。
