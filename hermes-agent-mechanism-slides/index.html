1. 什么是 Hermes Agent

一个以大语言模型为"大脑"、以工具为"四肢"、以记忆为"经验"的生产级 AI 智能体框架。

核心定义

  • 智能体 (Agent)：能感知环境、做出决策、执行动作的自主系统
  • LLM 驱动：以 LLM 为推理核心，自然语言作为交互界面
  • 工具增强：通过工具调用 (Function Calling) 突破纯文本限制
  • 持久化：跨会话记忆 + 技能库 + 用户画像

三大设计目标

  • ① 可执行：能跑 shell、读写文件、发邮件、操作浏览器——不止"说"
  • ② 可扩展：工具/技能以插件方式按需加载，60+ 工具 & 30+ 技能
  • ③ 可记忆：用户偏好、项目约定、环境工具 quirks 跨会话保留
Hermes ≠ 传统 ChatBot：它是一个能动手的"AI 工程师"——你给目标，它自己拆解任务、调用工具、迭代、产出结果。

3. 核心机制 ① · 工具调用 (Function Calling)

Hermes 与"裸 LLM"最大的区别：LLM 可以"开方子"，由系统"抓药执行"。

用户："找出 ~/auto 里所有 slides" → LLM 思考 → tool_call: terminal("ls ~/auto | grep slides") → 系统执行 → 返回结果 → LLM 整理回答

工具调用 4 步循环

  1. LLM 接收 prompt + 工具 schema
  2. 输出 tool_use 块 (name + args JSON)
  3. 系统执行工具，结果回填对话
  4. LLM 继续推理 → 再次调用或给最终回答

为什么这是革命性

  • 突破幻觉：执行 = 事实
  • 突破纯文本：可写代码、画图、发邮件
  • 可验证：每步结果可审计
  • 可组合：N 个工具 = 指数级能力

4. 核心机制 ② · 记忆系统 (Memory)

没有记忆，AI 每次都是"失忆患者"。Hermes 用三层记忆结构实现跨会话连续性。

① 短期 (in-conversation)

当前对话的 context window。LLM 看到的全部 message + tool 调用的"工作记忆"。

限制：context 长度有限 (8K-200K tokens)，长对话会"忘掉"早期内容。

② 长期 (memory tool)

跨 session 持久化的 agent notes，含环境事实、用户偏好、工具 quirks。

关键：每次新会话自动注入 system prompt，相当于"前情提要"。

③ 档案 (user profile)

关于用户本人的事实：职业、姓名、孩子学校、常用语言。

与 agent memory 分离，避免把"自我笔记"和"用户档案"混淆。

例：用户的 cron 任务 ID、163 邮箱授权码路径、Web 搜索被拦的 workaround——这些都属于 agent memory，下次开会话自动加载。

5. 核心机制 ③ · 技能加载 (Skills)

Skills = "专家手册"。当任务匹配某 skill 时，Hermes 自动加载该 skill 的工作流。

检测任务关键词→ 匹配 skill→ 加载 SKILL.md→ 执行预设工作流

Skill 组成

  • YAML frontmatter：name、description、触发关键词
  • Markdown 正文：触发场景、推荐步骤、坑点、验证清单
  • linked_files：templates/、references/、scripts/
  • 分类：devops / research / media / mlops / ...

与"工具"的区别

维度工具 (Tool)技能 (Skill)
形态代码 function文档 + 流程
调用方LLM 调Agent 自己加载
粒度原子动作端到端工作流
例terminal()academic-conference-survey

6. 核心机制 ④ · 子代理委派 (delegate_task)

当任务太大 / 太独立时，主 Agent 派生 子代理，隔离 context 并行执行。

两种调用模式

  • 单任务：goal=... + context + toolsets
  • 批量并行：tasks=[...]，最多 N 个并发 (默认 3)
  • 子代理拿不到主 Agent 的记忆，只接收你写的 context
  • 子代理不能调 clarify、memory、send_message

何时该派生子代理

  • 3+ 工具调用 的独立子任务
  • 需要 并行 处理多个工作流 (如同时抓 5 个会议)
  • 子任务会产生 大量中间输出，污染主 context
  • 子任务需要独立工具集 (如 web-only)
⚠️ 坑：子代理不稳定。实测"调研+写长文"任务 600s 超时返回空 summary。复杂任务优先自己做，只把机械/并行部分委派。

7. 核心机制 ⑤ · 任务规划 (Todo)

面对 3+ 步骤的复杂任务，Hermes 用 todo 工具做"看板管理"——把脑内思考外化为可见列表。

1. 分析任务→ 2. 写 todo list→ 3. 逐项执行→ 4. 标记完成→ 5. 交付
idcontentstatus
1设计 slides 内容结构 (22 页)completed
2创建单文件 HTMLin_progress
3浏览器视觉检查 + 溢出扫描pending
4更新根 index.htmlpending
5git add + commit + pushpending

关键：同时只一个 in_progress。完成即标 completed；失败则 cancel 并加 revised item。Todo 是 Agent 的"工作记忆外挂"。

8. 核心机制 ⑥ · 代码执行 (execute_code)

让 Hermes 拥有"自我编程"能力：用 Python 脚本批量调用工具，处理中间数据。

两种代码执行方式

  • execute_code：在 Hermes runtime 内跑 Python，可直接调 terminal()、read_file()、patch() 等
  • terminal：直接执行 shell 命令
  • 限制：5 分钟超时、50KB stdout、每脚本最多 50 次工具调用

什么时候用 execute_code

  • 3+ 工具调用 且中间需要处理逻辑
  • 需要条件分支 (if X then Y else Z)
  • 需要循环 (抓 N 页、处理 N 文件)
  • 需要重试/容错 (retry with backoff)
  • 需要过滤/聚合 大量结果

例：抓取 100 篇 arXiv 论文 → 用 execute_code 解析 JSON → 主题分类 → 输出报告。 比 100 次单独 terminal() 调用稳定得多。

10. 思考循环 (Reasoning Loop)

每次 LLM 推理，Hermes 强制 think → act → observe 三段循环，确保可解释可调试。

┌─ Turn 1 ──────────────────────────────────────┐ │ 🧠 THINK: "用户要发邮件，需先查收件人" │ │ 📤 OUTPUT: tool_call(read_file) │ └──────────────────────────────────────────────┘ ↓ ┌─ 系统执行 ───────────────────────────────────┐ │ terminal() → "地址: x@y.com" │ └──────────────────────────────────────────────┘ ↓ ┌─ Turn 2 ──────────────────────────────────────┐ │ 🧠 THINK: "需要 SMTP 配置" │ │ 📤 OUTPUT: tool_call(read_file ~/.auth) │ └──────────────────────────────────────────────┘ ↓ ... (循环 N 轮) ... ↓ ┌─ Turn N+1 ────────────────────────────────────┐ │ 🧠 THINK: "信息齐了，可以发" │ │ 📤 OUTPUT: tool_call(himalaya send) + 文本 │ └──────────────────────────────────────────────┘

循环终止条件：① LLM 输出最终回答（无 tool_call） ② 达到 max_iterations ③ 工具报错且不可恢复。

11. 典型工作流 · "AI 早报 cron"端到端拆解

从用户提出"每天 5 点发 AI 早报"到稳定运行 5 天，Agent 走过的完整路径：

对话侧 (主 Agent)

  1. 用户："建个 cron 每天 5 点发 AI 早报到 QQ 邮箱"
  2. Agent：加载 cronjob-scheduler + email-163 skills
  3. 读 memory：用户已有 163 邮箱配置 + 收件地址
  4. 规划：todo 列 3 步 (写 prompt → 调 himalaya → 创建 cron)
  5. 调 cronjob create 提交任务
  6. 告诉用户：cron ID + 验证方法，不主动跑

Cron 侧 (隔离 session)

  1. 05:00 触发，新 session 自动加载 cron prompt + skills
  2. 执行 prompt：抓 24h AI 新闻 → 选 10 条 → 翻译
  3. 调 terminal 用 himalaya 发邮件
  4. 最终回答自动 deliver 到用户当前对话
  5. 完成，下次 05:00 重复

一个 cron 任务 = 一个 prompt + skills + deliver target。session 是隔离的，所以 cron 里看不到主对话 history。

12. 运行时沙箱 (Sandbox)

Agent 的"四堵墙"：workdir、env、toolsets、timeout，把风险圈在范围内。

维度机制例子
工作目录 workdir 参数锁定 cwd，terminal 命令默认在 workdir 跑 设 workdir=~/auto，命令相对路径都基于此
环境变量 可注入额外 env vars (如 API key) cron 注入 OPENAI_API_KEY，子任务内可用
工具集裁剪 enabled_toolsets 只加载必要工具组 研究子任务只开 ["web", "terminal", "file"]
超时控制 terminal 最多 600s，execute_code 5min，工具 50 次/脚本 防止 Agent 卡死或无限循环
Skill 隔离 cron 任务只看到 prompt 里 attach 的 skills 学术 cron 看不到 apple/email skills

13. 安全机制 · vet / tirith 兜底

Agent 权限大 = 风险大。Hermes 在 工具执行前 增设安全审批层。

LLM 输出 tool_call → vet / tirith 静态扫描 → 风险等级评估 → 低：直接执行 | 高：弹审批

典型拦截规则

  • rm -rf / · dd if= · 危险设备写入
  • 对外发邮件/消息 (需用户确认)
  • 支付/账户/密码类操作
  • 修改 ~/.ssh/、~/.config/

用户体验取舍

  • 低风险：自动放行，不打扰
  • 中风险：展示动作，给 undo 机会
  • 高风险：必须人工审批
  • 所有审批有日志，可事后审计

14. 多平台集成 (Multi-Channel)

同一个 Agent 实例，同一份 state，通过不同前端触达——这是 Hermes 与单点 chatbot 的本质区别。

消息平台

  • Telegram (主)
  • Discord
  • Slack
  • Signal
  • Matrix
  • WhatsApp / iMessage

办公 & 协作

  • Email (163/QQ/Gmail via himalaya)
  • Google Workspace (Gmail/Calendar/Drive)
  • Notion / Linear / Obsidian
  • Feishu (飞书文档/云盘)

设备 & IoT

  • HomeAssistant (智能家居)
  • Philips Hue / openhue
  • Apple Reminders / Notes / FindMy
  • Spotify / 音乐

关键：消息里提到的事，CLI也能继续做——共享 context、共享 memory、共享 todo 状态。

15. 定时任务 (Cron) · 7×24 自动化

把"每天重复"的事封成 cron，Agent 自主执行 + 自动 deliver。

用户指令 → cronjob create → 存 schedule + prompt + skills → 到点触发 → deliver 到原对话

当前用户的 cron 三件套

  • 6cdb0bdc · AI 早报 · 05:00 CST → QQ 邮箱
  • c7025229 · 学术论文日报 · 06:00 CST · arXiv 10-20 篇
  • 011ef8a2 · AI+教育前沿日报 · 04:00 CST

cron 的安全约束

  • 新 session 跑，看不到主对话 history
  • prompt 必须 自包含（含必要 context）
  • 不能递归调 cronjob create
  • 最终回答自动 deliver，可指定 chat/topic

16. Hermes vs 传统 LLM (ChatBot)

维度传统 LLM / ChatBotHermes Agent
能力边界只能输出文本文本 + 工具调用 + 真实世界操作
记忆仅当前 session，重启即失忆三层记忆 (短期/长期/用户档案)，跨会话
主动性被动响应"一问一答"可主动：cron 触发、子代理委派、后台任务
知识更新训练截止日冻结实时搜索 (arxiv/web) + 读本地文件
错误恢复幻觉且无法自检tool 结果可验证，失败可重试，可 fallback
可扩展性prompt 越狱为主工具/技能/MCP 插件化扩展
审计无完整 tool call log + 安全审批 + 会话搜索
成本每次 LLM 推理LLM + 工具调用 + 沙箱开销，更贵但更值

17. Hermes vs 其他 Agent 框架

框架典型用户核心差异
LangChain / LangGraph Python 开发者搭 pipeline 图论编排，灵活但要写代码；Hermes 是"已搭好的 graph"

Hermes (本套 slides 主角) 个人 AI 工程师 / 研究者 本地 + 跨平台 + 长期记忆 + 技能库 + 安全审计

18. 优势 vs 局限

✓ 优势

  • 可执行：真正动手做事，不止"建议"
  • 可记忆：跨会话连续，越用越懂你
  • 可扩展：工具 + skills + MCP 插件化
  • 本地优先：隐私好、可访问本地文件/SSH
  • 多平台：CLI/TG/邮件/cron 触达
  • 安全审计：vet/tirith + 完整日志
  • 可调试：tool call 链路可追溯

✗ 局限

  • Context 上限：长对话会"早期遗忘"
  • Tool 错误放大：一个失败调用可能连环错
  • 成本：比裸 LLM 调用贵 3-10x
  • 延迟：多轮 tool call 比单轮慢
  • 子代理不稳：复杂任务超时率高
  • Web 搜索受限：Cloudflare/反爬经常拦
  • 需用户参与：高风险必须人审批，不能完全放手

20. 总结 · 智能体的"心脏"长什么样

Hermes = LLM 大脑 + 工具四肢 + 记忆经验 + 沙箱边界 + 多平台感官

记住这 6 句话

  1. 工具调用是 Agent 与 ChatBot 的分水岭
  2. 三层记忆让 AI 从"金鱼"变成"管家"
  3. 技能 + 工具的二维扩展 = 指数级能力
  4. 子代理用隔离换并行，但不滥用
  5. 沙箱 + 审计 = 可上生产的必要条件
  6. 多平台 + cron = 从"问答"变"7×24 助理"
