量化的数学定义

把 FP32/FP16 浮点张量 x 映射到 INT8/INT4 等低位宽整数的可逆变换。

对称量化 INT8

scale = max(|x|) / (2b-1 - 1)
xq = clamp(round(x / scale), -2b-1, 2b-1-1)

  • 零点是 0,适合权重(分布对称)
  • 硬件友好:TensorRT / TFLite 默认

非对称量化 UINT8

scale = (max - min) / (2b - 1)
zero_point = round(-min / scale)
xq = clamp(round(x / scale) + zp, 0, 2b-1)

  • 零点 ≠ 0,适合激活值(ReLU 后分布偏正)
  • 精度略高,需存储 zero_point

数值格式

整数 vs 浮点

  • INT8:推理最常用,4× 压缩
  • INT4:LLM 部署主流,8× 压缩
  • FP8:E4M3 / E5M2,训练推理均用
  • FP4:NVIDIA/MX 格式,2024 起步

核心矛盾

精度 vs 效率

  • 位宽越低 → 体积/算力越省
  • 位宽越低 → 量化误差越大
  • LLM 在 INT4 已够用,INT2 / 1-bit 仍有精度挑战

误差来源

三件事毁掉精度

  • outlier:少数大值霸占 scale
  • rounding:四舍五入丢精度
  • distribution shift:训练 vs 推理分布差

量化粒度:per-tensor → per-token → per-group

粒度越细,精度越高,计算/存储开销也越大。LLM 量化普遍在 per-group(128/64) 取得最佳平衡。

粒度scale 数精度开销典型场景
per-tensor 1 个 / tensor 低 极低 早期 CNN,INT8 推理
per-channel C 个 (output 维度) 中 低 CNN weight 量化标配
per-token 每个 token 一个 高 中 LLM activation 量化
per-group 每 g 个元素一组(典型 g=128/64) 高 中-高 GPTQ / AWQ / LLM.int8() 默认
sub-channel 亚 channel 级 高 高 FP8 训练 / Fine-grained
经验法则:LLM 量化时,weight 用 per-group (g=128),activation 用 per-token(或 per-dynamic),KV cache 用 per-head / per-token。这是 2023 年以来 LLM 量化的"标配三件套"。

量化什么?4 类对象 × 4 类方法

量化的对象决定了挑战类型。LLM 时代,KV cache 和 activation 的量化比 weight 更难。

① Weight 量化

最成熟 · 收益最直接

  • W4A16 / W4A8 / W3A16 是 LLM 主流
  • 技术:GPTQ / AWQ / OmniQuant
  • 难点:outlier channel,需 special handling

② Activation 量化

推理时最不稳定

  • 动态范围大,异常值集中
  • 技术:SmoothQuant / OmniQuant / AffineQuant
  • 难点:在线统计 vs 离线校准

③ KV Cache 量化

长上下文核心瓶颈

  • 显存随 sequence length 线性增长
  • 技术:KIVI / KVQuant / ZipCache
  • 难点:Key 通道异常值,Value 平稳

④ Gradient 量化

分布式训练必需

  • FP8 训练已成大模型标配
  • 技术:ZeRO / FP8 all-reduce
  • 难点:通信 vs 收敛

⑤ Attention 量化

新兴

  • Attention map 量化
  • Q @ K^T / softmax 量化
  • 难点:Softmax 对极端值敏感

⑥ Embedding 量化

被低估的优化点

  • 大 embedding table 占用大量显存
  • 技术:Product Quantization / Binary
  • 难点:vocabulary size 大,outlier 多

方案分类树:什么时候用什么方法?

从"训不训练"和"有没数据"两个维度,把方案切成 4 象限。

你的场景是什么? ├── 【有完整训练数据 + 可重训】 ──→ QAT (Quantization-Aware Training) │ ├── 经典: PACT(2018) / LSQ(2019) / DSQ(2019) │ ├── 通用: LSQ+ / QAT with KS(2022) │ └── LLM: LLM-QAT(2024) / EfficientQAT(2024) │ ├── 【无训练数据 + 有少量校准集】 ──→ PTQ (Post-Training Quantization) │ ├── CNN: BRECQ(2021) / PD-Quant(2023) │ ├── ViT: RepQ-ViT(2023) / I-ViT(2023) │ ├── LLM: GPTQ(2022) / AWQ(2023) / SmoothQuant(2022) │ └── 扩散: PTQD(2023) / Q-Diffusion(2023) │ ├── 【有权重 + 需要微调】 ──→ 量化 + PEFT │ ├── QLoRA(2023) 4-bit base + LoRA adapter │ ├── QA-LoRA(2023) / LoftQ(2023) │ └── LLM-QAT(2024) data-free distillation │ └── 【从头训练 + 极致压缩】 ──→ 低比特原生训练 ├── 1.58-bit: BitNet b1.58(2024) ⭐ ├── 1-bit: BitNet(2023) └── 1-bit Adam: 1-bit LLM 大规模训练
2023-2026 的主流:PTQ + 少量 calibration(99% 工业场景),QLoRA(微调场景),1-bit 训练(新前沿)。QAT 仅在精度要求极高时用。

训练后量化 PTQ:不训模型的压缩范式

PTQ 是工业界最常用的方案:训练好的 FP 模型,只用 几百到几千个样本 做 calibration,直接得到低比特模型。

FP32 预训练模型teacher
→
收集激活统计量min/max/percentile
→
计算 scale/zero_pointcalibration
→
量化权重 + 插入 fake-quantinference-ready

优势

  • ✓ 无需训练数据(可 data-free)
  • ✓ 几分钟到几小时出模型
  • ✓ 适合 LLM 等大模型

挑战

  • ✗ 极低比特(INT4 / INT2)精度差
  • ✗ 依赖 calibration set 质量
  • ✗ 异常值敏感

关键技术点

  • 校准算法:MinMax / Percentile / KL / MSE
  • 逐层 / 逐块重建:BRECQ 思想
  • 混合精度:敏感层保留 FP

PTQ 的核心算法步骤

从 calibration 到得到 INT 模型,4 步流程。

1. 选择量化粒度per-tensor/channel/group
→
2. 校准 scale/zero_pointminmax / KL / histogram
→
3. 量化权重 / 激活fake-quant / rounding
→
4. 评测 + 调优校准集 / 验证集

① MinMax 校准

最简单 · 工业默认

scale = max(|x|) / 127
zp = 0 (对称)

优点:快速 / 缺点:outlier 毁掉精度

② Percentile 校准

截断 outlier

clip = percentile(x, 99.99)
scale = clip / 127

SmoothQuant 内部用类似思路

③ KL 散度校准

TensorRT 默认

min KL(FP_hist || INT_hist)
选择最优 threshold T

数学最优 / 计算略慢

④ 优化方向(2023+)

· AdaRound(2020):每个 weight 学 soft-rounding · BRECQ(2021):block 重建,跨层优化 · PD-Quant(2023):用预测差异度指标找敏感层 · BitSplit(2020):可微 PTQ

代表作 · BRECQ(2021)· 49 引

Pushing the Limit of Post-Training Quantization by Block Reconstruction

问题

  • 传统 PTQ 只逐层优化,没考虑层间依赖
  • cross-layer 误差累积,精度差

核心思想

  • 把模型切成 block(2-3 层一组)
  • 在每个 block 内部,重建输出分布
  • 用 L2 距离 + 激活相似度作为 loss

贡献

  • 4-bit ResNet-18 ImageNet 首次 无损
  • 首次证明 block-level PTQ 优于 layer-level
  • 开启 block-reconstruction 系列工作
启示:PTQ 的"层"应该比单层大,比整模型小。block 重建 思想被 PD-Quant / BQ-Nets 等多篇后续工作继承。

代表作 · PD-Quant(2023)· 67 引

Post-Training Quantization Based on Prediction Difference Metric

问题

  • 混合精度 PTQ 关键:如何判断层敏感度?
  • 传统方法:参数量 / Hessian 迹 / SNR
  • 这些指标和最终精度相关性弱

核心思想

  • 直接用 预测差异(prediction difference)作指标
  • 对每层尝试不同 bit width,看对最终输出的影响
  • 引入超网 / 搜索算法分配 bit

贡献

  • 首个用 "end-to-end prediction" 而非 "中间特征" 评估敏感度
  • ResNet-50 / MobileNet 在 4-bit 显著优于 BRECQ
  • 提出 PD-Quant 搜索算法 自动分配 bit
启示:混合精度 PTQ 的"敏感度指标"本身是个研究问题。"预测差异"是比 Hessian 迹更直接的代理指标。

前沿:扩散模型的 PTQ

Stable Diffusion 推理 20-50 步,每步 UNet,极慢。量化是刚需。

PTQD(2023)· 13 引

Post-Training Quantization for Diffusion Models

  • 发现:扩散模型各时间步误差敏感性差异巨大
  • 提出:时间步相关的混合精度
  • 关键 insight:前面几步对噪声敏感,需保留 FP

Q-Diffusion(2023)· 112 引

Quantizing Diffusion Models

  • 首个端到端 PTQ 流水线 for Stable Diffusion
  • 对 UNet 各组件分别量化(权重 / 激活 / shortcut)
  • 校准噪声样本,跨时间步共享 scale

挑战

· 扩散模型迭代 20-50 步,误差累积放大 · 不同时间步激活分布差异极大 · 文本条件(text embedding)难量化 · 评分蒸馏(guidance scale)放大误差

2024 趋势:时间步自适应 bit 分配 + CFG 兼容量化。这仍是一个有空间的方向。

量化感知训练 QAT + STE

QAT 在训练阶段就模拟量化误差,让模型"适应"低精度。核心是让梯度穿过不可微的 round 操作。

STE: Straight-Through Estimator

forward: y = round(x) · scale
backward: ∂L/∂x ≈ ∂L/∂y (把 round 看作恒等映射)

QAT 的灵魂:让不可微的量化在反向传播中"直传",从而端到端可训练。

QAT 完整流程

5 步

  • ① 准备 FP 预训练模型
  • ② 插入 fake-quant 节点
  • ③ 少量 epoch 微调(1-3 epoch)
  • ④ 评估 INT 模型精度
  • ⑤ 导出推理引擎

核心难点

  • STE 误差:round 不是恒等映射,前向与反向不一致
  • 梯度消失:超低比特(INT2 / 1-bit)梯度极小
  • 训练成本:QAT 仍需完整数据集 + 多 epoch

2024+ 趋势

  • ✓ LLM-QAT(2024):data-free QAT for LLM
  • ✓ EfficientQAT(2024):block-wise 训练
  • ✓ BitDistiller(2024):QAT + 蒸馏

经典 · PACT(2018)· 720 引

Parameterized Clipping Activation for Quantized Neural Networks · Cho & Kung

问题

  • 激活分布的 outlier 让 INT8 精度崩溃
  • 固定 clip 阈值无法适配不同层

核心思想

  • 把 clip 阈值 设为 可学习参数
  • 每个 activation channel 一个 clip 值
  • 训练时与权重一起被优化

贡献 & 影响

  • 首个 可学习激活 clip 的 QAT 方案
  • ImageNet ResNet-20 2-bit 几乎无损
  • 被 LSQ / PACT+ / DSQ 等大量后续工作继承
启示:量化参数(阈值/clip 值/步长)本身可以学习,这打开了"可微量化"的大门。

经典 · LSQ(2019)· 296 引

Learned Step Size Quantization · Esser et al. (Facebook)

问题

  • PACT 只学 clip,step size 仍固定
  • step size 对量化误差影响大,需要自适应

核心思想

  • 把 量化步长 s 设为 可学习参数
  • 对 weight 和 activation 分别学 s
  • 引入梯度 scaling,避免 s 训练不稳定

贡献 & 影响

  • ImageNet 首次 3-bit ResNet 接近 FP 精度
  • 成为 QAT 的"事实标准"基线
  • LSQ+ (2020) 进一步支持 mix-precision
启示:把"step size"作为可学习参数,虽然简单,却极大释放了 QAT 的精度。BitDistiller(2024) / EfficientQAT(2024) 都继承这一思想。

前沿 · LLM-QAT(2024)· 107 引 + EfficientQAT(2024)· 20 引

把 QAT 搬到大模型时代

LLM-QAT(2024)· Meta

Data-Free QAT for LLM

  • 挑战:LLM 没有训练数据可用
  • 用 FP 模型自生成数据(self-distillation)
  • 对 attention / FFN / KV cache 全量化
  • LLaMA-2 7B 在 INT4 上 perplexity 接近 FP16

EfficientQAT(2024)· 20 引

Block-wise QAT 加速

  • 挑战:LLM 端到端 QAT 显存爆炸
  • 把模型切成 block,block 内独立 QAT
  • 两阶段:先 PTQ 初始化,再 block-wise QAT
  • LLaMA-2 70B INT2 在单卡 A100 即可训练

共同 insight

· LLM 的 QAT 必须 避免端到端,block-wise + 自生成数据是关键 · 两阶段 PTQ → QAT 是高效范式 · 蒸馏 + QAT 结合能进一步提精度(BitDistiller 2024)

LLM 量化的特殊挑战

传统 CNN 的 PTQ/QAT 套路搬到 LLM 上,直接失效。原因有三:

① Activation Outlier

少数大值霸占 scale

  • LLM 激活有 重尾分布(heavy-tailed)
  • 少数 channel 异常值达 100× 中位数
  • 直接 MinMax 量化 → 整张图被"压扁"

② 模型规模

7B-405B 参数

  • 端到端 QAT 显存爆炸
  • 梯度反传占资源
  • 需要 block-wise / PEFT 方案

③ Calibration 难

依赖少量样本

  • Transformer attention 复杂
  • LayerNorm / Softmax 不易量化
  • 分布 shift 在 autoregressive 时累积
LLM 量化的"第一性原理":outlier 是头号敌人。所有 SOTA 方法(AWQ / SmoothQuant / OmniQuant)核心都是在 不同维度 处理 outlier。

代表作 · LLM.int8()(2022)· 114 引

8-bit Matrix Multiplication for Transformers at Scale · Dettmers et al.

问题

  • 175B GPT-3 在 INT8 推理会崩
  • outlier 维度 (~0.1% feature)毁掉精度

核心方案

  • Vector-wise Quantization:内积分两半
  • · outlier 维度 → FP16 矩阵乘
  • · 普通维度 → INT8 矩阵乘
  • · 两部分加和

贡献 & 局限

  • 首次 让 >6B LLM 跑 INT8 不掉点
  • bitsandbytes 库沿用至今
  • 局限:混合精度有 ~20% 速度损耗
启示:"outlier-aware mixed-precision" 思想是后续所有 LLM 量化方法的"种子"。AWQ / SmoothQuant / OmniQuant 都在不同维度发展这个思想。

代表作 · GPTQ(2022)· 130 引

Accurate Post-Training Quantization for Generative Pre-trained Transformers · Frantar et al. (ICLR 2023)

问题

  • 传统 OBQ(Optimal Brain Quantization)对 LLM 太慢
  • OBQ 逐个 weight 优化,无法扩展到 175B

核心方案

  • 用 二阶信息(Hessian 逆)做列方向量化
  • 逐列量化 + 误差补偿
  • 利用 Cholesky 分解 高效求 Hessian 逆

贡献 & 影响

  • BLOOM-176B 3-bit 推理 接近 FP16 精度
  • 单卡 A100 几小时完成 175B 量化
  • AutoGPTQ / GPTQModel 等开源实现广泛使用
启示:把二阶优化(scale-aware error compensation)扩展到 LLM 级别,是"算法可扩展性"的胜利。

代表作 · SmoothQuant(2022)· 99 引

Accurate and Efficient Post-Training Quantization for Large Language Models · Xiao et al. (MIT)

问题

  • LLM 激活 outlier 让 INT8 量化难
  • Outlier 通常出现在 固定 channel

核心方案

  • 数学恒等式:W·X = (W·diag(s)-1) · (diag(s)·X)
  • 把 activation 的难度"迁移"到 weight
  • s 选为 s = max(|X|)α / max(|W|)1-α,α=0.5

贡献 & 影响

  • OPT-175B / BLOOM-176B W8A8 几乎无损
  • 无需训练数据(纯 PTQ)
  • 思路简单,工程化友好
启示:"等量难度迁移" 是处理 activation outlier 的优雅思路。OWQ / Outlier Suppression+ 等都继承。

代表作 · AWQ(2023)· 172 引

Activation-aware Weight Quantization for LLM Compression · Lin et al. (MIT, GetMobile 2025)

观察

  • LLM 权重中 1% salient channel 保护后,精度不掉
  • salient channel = activation 大的 channel

核心方案

  • 用 activation 统计找 salient weight channel
  • 对 salient channel 保留 更高位宽(per-group 量化)
  • 或对 salient channel scale up(等价效果)

贡献 & 影响

  • Llama-2 7B/13B/70B 4-bit 几乎无损
  • 推理速度提升 3.6×
  • llm-awq 开源,TensorRT-LLM / vLLM 集成
启示:"activation-aware" 是 LLM 量化最重要的设计原则之一。同类思想被 OWQ / OmniQuant / AffineQuant 继承。

代表作 · QLoRA(2023)· 496 引

Efficient Finetuning of Quantized LLMs · Dettmers et al. (华盛顿大学, NeurIPS 2023)

目标

  • 65B 模型 单卡 48GB 微调
  • 保持 FP16 16-bit 任务性能

三大创新

  • ① NF4:4-bit NormalFloat,信息论最优
  • ② Double Quant:对量化常数再量化,省 0.4 bit/param
  • ③ Paged Optimizers:显存溢出自动分页到 CPU

贡献 & 影响

  • 引用数 496 — 整个量化领域的全网最高引
  • Guanaco 模型 / 大量 PEFT 后续工作
  • bitsandbytes 库 4-bit base + LoRA 成为标配
启示:量化不必是为了推理,也是为了微调。"量化 + PEFT"打开新维度。LoftQ / QA-LoRA 都在这个范式下。

代表作 · OmniQuant(2023)· 14 引 · ICLR 2024

Omnidirectionally Calibrated Quantization for Large Language Models · Shao et al.

思路

  • 把 PTQ 的超参(clip ratio、scale)做成 可学习
  • 但保持 无训练数据(data-free)

两大模块

  • Learnable Weight Clipping (LWC):学每个 channel 的 clip
  • Learnable Equivalent Transformation (LET):学 affine 变换

效果

  • Llama-2 7B W2A16(2-bit 权重)→ 接近 FP16
  • 多个 LLM 家族均 SOTA(2024-2025)
  • OmniQuant + GPTQ = 进一步提升
启示:"PTQ + 可微调参" 是介于 PTQ 和 QAT 之间的优雅中间地带。AffineQuant(2024) 是其改进版。

代表作 · QuaRot(2024)+ SpinQuant(2024)

用旋转矩阵把 outlier 抹平

QuaRot(2024)· 3 引

Outlier-Free 4-Bit Inference in Rotated LLMs · Ashkboos et al.

  • 用 随机 Hadamard 旋转 抹平 outlier
  • 在 每一层 之前插入旋转矩阵
  • 数学等价的变换,不改变输出
  • Llama-2 70B W4A4 几乎无损

SpinQuant(2024)· 6 引

LLM Quantization with Learned Rotations · Liu et al. (Meta)

  • 把 QuaRot 的"随机旋转"换成 学到的旋转
  • 在 calibration set 上优化旋转矩阵
  • LLaMA-2 / LLaMA-3 / Mistral 均 SOTA
  • Meta 已开源,被生产系统采用
2024 新范式:几何变换(旋转/缩放)预处理 → 解决 outlier → 再量化。这是一条"治标治本"的新路线。

代表作 · KIVI(2024)· 6 引 · ICLR 2024

A Tuning-Free Asymmetric 2bit Quantization for KV Cache · Liu et al.

问题

  • 长上下文 LLM 推理时 KV cache 占显存大头
  • LLaMA-7B + 100K 上下文,KV 占 ~14GB
  • 直接 KV 量化会掉点

核心观察

  • Key: 同一 channel 在不同 token 表现一致(都 outlier)
  • Value: 同一 token 在不同 channel 表现一致
  • 两种分布特征 完全不同

方案

  • Key: per-channel 量化(2-bit)
  • Value: per-token 量化(2-bit)
  • Tuning-free,直接 PTQ 应用
  • Llama 7B + 2-bit KV → 6.7× 显存压缩
延伸:KVQuant(2024) / ZipCache(2024) / MiKV(2024) / KVQuant + KIVI 混合精度(2025)——这是 长上下文 LLM 部署 的核心战场。

代表作 · BitNet b1.58(2024)· 37 引

The Era of 1-bit LLMs: All Large Language Models are in 1.58 Bits · Ma et al. (微软)

突破

  • 1.58 bit/weight = {-1, 0, +1}
  • 权重 原生训练 而非后量化
  • 3B 模型 超过 LLaMA 3B FP16 在多个任务

技术细节

  • 激活用 8-bit,KV 用 4-bit
  • 用 sign() 函数做前向,STE 做反向
  • 三值权重的 entropy 比二值高(信息更多)

意义 & 局限

  • 开创 "原生 1-bit LLM" 新范式
  • bitnet.cpp 2025 推理速度 5-7× FP16
  • 局限:仍需大量 GPU 训练资源
为什么是 1.58?三值 {-1, 0, +1} 的信息量 = log₂(3) ≈ 1.585 bit,刚好是 FP16 信息的 1/10。这是 信息论最优的极简选择。

前沿 · AffineQuant(2024)· 1 引 + FlatQuant(2024)· 2 引

让量化参数"足够灵活"

AffineQuant(2024)· Li et al.

Affine Transformation Quantization for LLMs

  • 把 OmniQuant 的 LET 模块换成 任意 affine 变换
  • 每个 layer 学一个 2×2 矩阵(channel 混合)
  • 相当于学到了 更灵活 的 outlier 平移
  • Llama-2 7B W2A16 PPL 6.13(OmniQuant 是 6.49)

FlatQuant(2024)· Sun et al.

Flatness Matters for LLM Quantization

  • 关键 insight:权重分布的"平坦度" 影响量化难度
  • 对 weight 和 activation 分别学 affine + 旋转
  • Llama-3 8B W4A4 接近 FP16(2025 刷新 SOTA)
  • 开源,已被生产系统集成
趋势:"量化前的预处理"(旋转、缩放、affine 变换)成为新前沿。从 GPTQ → SmoothQuant → AWQ → SpinQuant → FlatQuant,预处理越来越复杂、灵活。

代表作 · QServe(2024)· 6 引

W4A8KV4 Quantization and System Co-design for Efficient LLM Serving · Lin et al. (MIT)

问题

  • W4A16 算法好但 推理慢
  • W4A4 算得快但精度差
  • 需要 算法-系统 协同

方案

  • Weight W4 + Activation A8 + KV KV4
  • 设计 Matmul 内核 解耦 W4 加载与 A8 计算
  • 端到端 GPU 推理服务系统

效果

  • Llama-3 8B 1.5× throughput vs FP16
  • 1.2× vs TensorRT-LLM W4A16
  • open-source github.com/mit-han-lab/qserve
启示:"W4A8KV4" 这种非均匀 bit 配置已成为 生产级 LLM 服务 的事实标准。算法-系统协同设计是 2024-2025 必经之路。

代表作 · T-MAC(2024)· CPU 上的 LUT 量化

CPU Renaissance for Table-based LLM Quantization · Wei et al. (微软)

问题

  • 低比特 CPU 推理(INT4/INT2)需要特殊 SIMD 指令
  • 传统 GEMM 路径在 异构 CPU(ARM/x86/RISC-V)难以统一

方案

  • 把 weight 预计算成 查找表(LUT)
  • 推理 = 查表 + 标量乘加
  • 统一 CPU 指令集,无需 SIMD

效果

  • Llama-2 7B 2-bit 在 Mac CPU 上 30 token/s
  • 在 RISC-V / ARM 上同样 SOTA
  • 4-bit Llama 跑赢 llama.cpp FP16
启示:算法-硬件协同 不止于 GPU。CPU 上的 LUT 量化是边缘部署的新方向。

视觉 Transformer 量化:ViT / Swin / DETR

ViT 类模型的激活分布比 CNN 更难量化:heavy-tailed,outlier 严重。

I-ViT(2023)· 113 引

Integer-only Quantization for Efficient ViT Inference

  • 首个 ViT 的 纯整数量化 推理方案
  • 解决 Softmax / LayerNorm 的整数量化
  • DeiT-S 8-bit 几乎无损,INT-only 推理加速 3.6×

RepQ-ViT(2023)· 91 引

Scale Reparameterization for PTQ of ViT

  • 核心:对 Softmax / LayerNorm 做 scale reparameterization
  • 把 PTQ 难以处理的非线性模块"吸收"到线性层
  • DeiT-S 4-bit 仍保持高准确率

其他工作

· NoisyQuant(2023)· 47 引 — 用量化噪声当"正则化",巧解 ViT 激活 heavy-tail · Q-ViT(2022) · PTQ4ViT(2022) · FQ-ViT(2022) · Swin-Quant(2023)(Swin Transformer 专用)

扩散模型量化:从 SD1.5 到 SD3 / FLUX

扩散模型是迭代去噪,每步 1 个 UNet forward。量化能省 50%+ 时间。

Q-Diffusion(2023)· 112 引

SD 端到端 PTQ 流水线

  • 对 UNet 权重量化 + shortcut 分支量化
  • 校准数据用 noise sample
  • W4A8 SD1.5 FID 几乎不变

PTQD(2023)· 13 引

时间步自适应量化

  • 发现各时间步误差敏感性差异巨大
  • 前面步骤(t 较大)需更高位宽
  • W4A8 SD 接近 FP16 效果

2024 进展

  • SD3 / FLUX(DiT 架构)量化
  • Video-LDM 量化
  • CFG(Classifier-Free Guidance) 兼容量化
挑战:CFG 放大误差(guidance scale 7.5 经常让 4-bit 失效)。CFG 兼容量化 是 2024-2025 的 open problem。

挑战

  • MQuant(2025) · OptiVLM(2025)

研究机会

  • · 视频 / 音频模态量化

Idea A · CFG 兼容的扩散模型量化

目标:CVPR 2026 / ICCV 2026 · 难度:中 · 时间:6-9 月

问题

  • CFG(Classifier-Free Guidance)放大量化误差
  • guidance scale 7.5 时,W4A8 SD1.5 FID 退化
  • 主流 PTQD / Q-Diffusion 都 忽略 CFG

技术路径

  • 分析 CFG 输出 = ε_cond + s·(ε_cond - ε_uncond)
  • 对 cond / uncond 两路分别量化
  • 联合优化 scale,让 误差在 CFG 后被抵消
  • 或:动态 bit allocation based on guidance scale

实验设计

  • SD1.5 / SDXL / SD3 / FLUX
  • MS-COCO / PartiPrompt 评测
  • FID / CLIP-score / 推理速度
  • 对比 PTQD / Q-Diffusion baseline

为什么能发

· CFG 兼容量化是 2024-2025 open problem(FLUX 量化时尤其严重)· 现有方法只考虑单步去噪,不考虑 CFG 放大 · 代码基础:Q-Diffusion + diffusers 都有现成 pipeline

Idea B · 量化模型的隐私攻击 / 防御

目标:S&P 2026 / USENIX Security 2026 / TDSC · 难度:中-高 · 时间:9-12 月

问题

  • 量化模型权重是 公开 的(下载方便)
  • 攻击者能否从量化权重反推 训练数据?
  • 量化本身是否提供 隐私保护?

攻击面

  • MIA(成员推断):反推某数据是否在训练集
  • Model Inversion:从权重反推训练样本
  • Quantization Leakage:round 误差透露梯度信息
  • Quantization-aware 隐私推断

防御 + 评估

  • 差分隐私 + 量化结合(DP-QAT)
  • 量化作为隐私机制(noise-aware quant)
  • 构建 量化隐私 benchmark

为什么能发

· 交叉领域:量化 × 隐私,S&P 喜欢看新攻击面 · 现有工作(Wei et al. 2023 "Q-sniffer")只做 FP,没系统化 · 实用威胁:HF Hub 上百万量化模型都是潜在攻击目标

Idea C · 1-bit LLM 的边缘设备部署

目标:MLSys 2026 / ASPLOS 2026 · 难度:高 · 时间:12-15 月

问题

  • BitNet b1.58 用 5-7× 推理加速,但只验证 GPU
  • 移动端 / IoT / 嵌入式设备(手机/树莓派)能否跑 1-bit LLM?
  • bitnet.cpp 2025 起步,生态不完善

技术路径

  • · 三值矩阵乘 (TMM) 的 ARM NEON 优化
  • · 1-bit 权重的稀疏化 + bit-packing
  • · 端侧 KV cache 压缩(2-bit + 滑动窗口)
  • · 端云协同:大模型在云,1-bit 在端

实验设计

  • 测试:手机 / 树莓派 / Apple Silicon / 高通 NPU
  • 1-bit BitNet b1.58 2B / 7B / 70B
  • 功耗 / 内存 / 速度 / 精度全对比
  • 对照:llama.cpp / T-MAC / MNN

为什么能发

· MLSys 偏好 系统 + 算法 协同工作 · 1-bit LLM 是 2025 公认新范式,端侧部署 几乎空白 · 实用价值:大模型真正"飞入寻常百姓家"

Idea D · 多模态协同量化(ViT + LLM)

目标:NeurIPS 2026 / ICML 2026 / CVPR 2026 · 难度:中-高 · 时间:9-12 月

问题

  • VLM(LLaVA/Qwen-VL) 量化时,ViT 和 LLM 独立处理
  • ViT 量化误差 累积 到 LLM,放大掉点
  • Modality gap 让 calibration 困难

技术路径

  • · Joint Calibration:ViT + LLM 一起校准
  • · 模态平衡:让 ViT 和 LLM 量化误差相当
  • · Projector 量化友好设计
  • · 视觉 token 压缩:减少 VLM 的输入长度

实验设计

  • LLaVA-1.5 / Qwen2-VL / InternVL2
  • VQA / MMBench / MMMU 评测
  • W4A8 vs W4A16 baseline 对比

为什么能发

· VLM 量化 2024-2025 几乎空白,蓝海 · NeurIPS 偏好 新模型 + 新方法 · 代码基础:transformers + llm-compressor 都有

Idea E · 量化友好的持续学习

目标:ICLR 2026 / TPAMI · 难度:高 · 时间:12-18 月

问题

  • LLM 持续学习会"灾难性遗忘"
  • 量化 + 持续学习 双重精度损失
  • 现有工作各自独立

技术路径

  • · 任务感知的量化位宽分配
  • · 重要参数(遗忘敏感)在量化中保留高位
  • · 量化 + EWC / SI 等正则化结合
  • · 数据回放 + 量化感知重训

实验设计

  • Continual T5 / Continual LLaMA
  • 15 个 NLU 任务序列
  • backward transfer / forward transfer 指标

为什么能发

· 持续学习 + 量化 几乎没人做 · 长期价值高:实用化 LLM 必须支持在线学习 + 边缘部署 · TPAMI 偏长文,可做系统化研究

  1. 为什么 LLM 的 INT4 量化在 2022-2023 才"突然"可行?
