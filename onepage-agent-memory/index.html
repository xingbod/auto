01

核心思想:LLM 没有原生记忆,Agent 需要外部大脑

STATELESS LLM → STATEFUL AGENT

LLM 每次调用都"失忆", 上下文窗口 8k-200k, 真实任务要持续学习、记住用户、避免重复错误。

LLM 裸模型
  • 状态: 无状态 (stateless)
  • 记忆: 仅当前 context
  • 限制: 窗口上限 8k-200k
  • 调用: 每次独立
AGENT 智能体
  • 状态: 跨 session 持久
  • 记忆: 多层外部系统
  • 扩展: 几乎无上限
  • 调用: 主动管理记忆

4 大记忆层级:仿人脑的分层设计

FOUR MEMORY LAYERS

借鉴人脑 (Atkinson-Shiffrin 模型), Agent 记忆分 4 层, 速度/容量/持久性各有取舍:

1
工作记忆
Working
当前 context: 系统提示 + 当前任务 + 近期对话。
token 上限 · 速度最快
2
短时记忆
Short-term
当前 session对话历史, 滑动窗口 / 摘要保留。
BufferMemory · Window
3
长时记忆
Long-term
跨 session持久化, 向量 DB + 知识图谱。
Pinecone · Zep · Mem0
4
程序记忆
Procedural
"如何做": 工具调用模式、行为模板、错误反思。
Reflexion · ReAct

RAG 是基础, 但要真做好 Agent 记忆, 还需要下面 6 个补充技术:

🔍 RAG 检索 RAG

05

新手最常踩的 4 个坑

COMMON PITFALLS
✗
"RAG = 完美记忆" 👉 RAG 只解决"检索"问题。还要反思、整合、主动管理, 不然检索错的记忆还是错。
✗
"记忆越多越好" 👉 记忆膨胀导致检索变慢、上下文污染。需要重要性评分 + 主动遗忘, 不是"全存"。
✗
"记忆 = 上下文" 👉 记忆是"仓库", 上下文是"取货窗口"。把全部记忆塞进 context = 浪费 token + 慢。
✗
"向量检索 = 语义检索" 👉 向量相似 ≠ 真正相关。需要混合检索 (BM25 + 向量) + 重排序, 纯向量经常跑偏。
