起点:SFT 解决了什么,没解决什么

先看清问题,再看 RL 怎么救场

SFT(监督微调)做了什么

问答数据 (问,答) → 模型 → 学会"问→答"格式

SFT 没解决什么

❌ 内容质量参差不齐

数据里有些答案漂亮、有些胡编,模型都学了。
"李白是个卖菜的大爷"也可能冒出来。

❌ 没有"偏好"概念

"哪个答案更好"这个信息 SFT 用不上,只有 loss 高低。

❌ 不能直接对齐人类价值观

有用性、诚实性、无害性这些 SFT 标不出来。

⚠️ 我们想要的

让模型"更想说"好答案, "更不想说"坏答案, 知道什么该说什么不该说。

强化学习基础:把 LLM 套进 RL 框架

术语对照表,先记住这张图

RL 术语LLM 中的对应例子
State s当前上下文(prompt + 已生成的 token)"介绍一下李白\n答:李"
Action a下一个要生成的 token"白"
Policy π(a|s)语言模型(给状态,输出 token 概率)P("白")=0.4, P("一")=0.1, ...
Reward r(s,a)对生成内容的人类打分流畅 +1, 答对 +2, 有害 -5
Trajectory τ一段完整的回答"白,字太白,号青莲居士..."

核心目标

max Eτ ~ π [ R(τ) ] ← 让模型期望回报最大化

难点:奖励函数 r 怎么来? 人类对每个 token 打分不现实,对整段回答打分信号又太稀疏。

4 / 21

最朴素的策略梯度:REINFORCE

起点:既然要最大化期望回报,就对 reward 大的轨迹求梯度

核心公式

∇J(θ) = Eτ ~ πθ [ R(τ) · ∇log πθ(τ) ]

直觉

  • 采样一段回答 τ,得到总奖励 R(τ)
  • 如果 R(τ) 高 → 加大这条轨迹出现的概率(∇log π)
  • 如果 R(τ) 低 → 降低

致命问题

高方差:每次只采一条轨迹,reward 波动巨大,训练极不稳定。

解决方案:加 baseline(用价值函数估计"平均期望"),变成 Actor-Critic。

这就是 PPO 出现前的状态:能用,但训不好。

5 / 21

PPO:让策略更新稳定下来

Proximal Policy Optimization,OpenAI 2017,RLHF 的事实标准

核心机制:clip 截断

LCLIP(θ) = E [ min( rt(θ)·At, clip(rt(θ), 1-ε, 1+ε)·At ) ]

其中 rt(θ) = πθ(at|st) / πθ_old(at|st),A 是优势(相对 baseline 的好坏)

直觉

  • rt 衡量"新策略相对旧策略的偏移倍数"
  • clip 在 [1-ε, 1+ε] (通常 ε=0.2) 之间,不让一次更新太猛
  • 有 critic 估计 At,降低方差

PPO 的三大组件

Actor (policy) → Critic (value) → Reward Model → Reference (SFT ckpt)

↑ 这就是 RLHF 内存爆炸的根源:4 个模型同时在显存里。

RLHF 的工程痛点

为什么大家开始想"砍掉一些东西"

😵 4 个模型同显存

policy + critic + reward + reference
对 7B 模型光 PPO 阶段就要 80GB+

🎢 训练不稳定

KL 系数、reward 缩放、clip range...
超参敏感,容易训崩

🎯 Reward Hacking

模型学会"骗"RM:
输出人类看着爽但实际没用的内容

🔧 实现复杂

需要训 RM,搭 PPO 循环,管理老/新 policy
调通一遍要几周

🐛 Critic 不准

value function 在稀疏奖励下估计偏差大
进一步拉低训练稳定性

💰 数据贵

偏好标注:每条 (好,坏) 对要请人打分
百万级标注 = 数十万美元

2023 年,Stanford 团队问:"能不能不要 RM、不要 critic,直接训 policy?" → DPO 诞生。

DPO 的核心洞察

Rafailov et al., 2023, Stanford

问题

RLHF 复杂,有没有办法把 RM 和 PPO 合二为一?

DPO 的回答

在带 KL 约束的 RL 优化下,最优 policy 的 reward 有一个解析形式,直接用 policy 自身就能算出来。

最优 policy 满足:

    π*(y|x)
r*(x, y) = β · log ——————— + 常数(与 y 无关)
    πref(y|x)

翻译成人话

  • reward ≈ policy 相对 reference 的"对数偏好偏移" × 温度 β
  • 不需要单独训 RM
  • 不需要 critic,不需要 PPO 循环
  • 只要有偏好对 + 监督学习式的 loss,就能训

这一招把"两阶段 + 强化学习"压成了"一阶段 + 监督学习"。

Bradley-Terry 偏好模型

DPO 推导的起点

核心假设

人类更喜欢 y好 的概率,只取决于两者的 reward 差:

P(y好 ≻ y坏 | x) = σ( r(x, y好) − r(x, y坏) )

说明

  • σ 是 sigmoid 函数,把任意实数压到 (0, 1)
  • reward 差越大 → 越确定"好答案更好"
  • reward 差为 0 → 50/50

这只是假设,不是 DPO 的创新

早在 1952 年 Bradley-Terry 就提出这个模型,广泛用于排位、推荐系统。

DPO 的贡献是:把 r 表达成 π 和 πref 的函数,代入这个式子,常数项被消掉。

10 / 21

从 Bradley-Terry 到 DPO 公式

一行数学,核心就这一行

Step 1:代入 r 的解析形式

r(x, y) = β · log( π(y|x) / πref(y|x) ) + 常数

Step 2:r(y好) − r(y坏),常数项抵消

Δ = β · [ log(π(y好|x)/πref(y好|x)) − log(π(y坏|x)/πref(y坏|x)) ]

Step 3:写成更直观的形式

logits_diff = β × (
    [log π(y好) − log π(y坏)]
  − [log πref(y好) − log πref(y坏)]
)

Step 4:DPO loss

L = − log σ( logits_diff ) ← 鼓励 logits_diff 变大变正

整个 DPO 训练,就是 监督学习式的最大化偏好对数似然。

DPO 数值演算:走一遍

具体数字,看看 loss 怎么下降

设定

prompt = "介绍一下李白" → chosen = "李白,字太白,号青莲居士..." → rejected = "李白是个卖菜的大爷。"

训练前:policy 与 reference 一致

log π(chosen)log π(rejected)内部差
πref (SFT)−2.50−2.700.20
π (训练前)−2.50−2.700.20
Δ = 0.20 − 0.20 = 0 → L = −log σ(0.1 × 0) = log 2 ≈ 0.693

训练 N 步后:policy 在 chosen 上推高,rejected 上压低

log π(chosen)log π(rejected)内部差
π (训练后)−1.80−3.902.10
Δ = 2.10 − 0.20 = 1.90 → L = −log σ(0.19) ≈ 0.603 ↓

policy 相对 reference 拉开差距,loss 下降,模型"敢说" chosen、"不敢说" rejected。

DPO 代码逐行解读

对照我们 scripts/03_dpo.py

# 1. 准备一对序列
ci, cm = encode_pair({**rec, 'answer': rec['chosen']},   tok, MAX_LEN)
ri, rm = encode_pair({**rec, 'answer': rec['rejected']}, tok, MAX_LEN)

# 2. policy 和 reference 分别算 log prob
lp_chosen    = sequence_logprob(policy, ci, cm)            # log π(y_好|x)
lp_rejected  = sequence_logprob(policy, ri, rm)            # log π(y_坏|x)
ref_chosen   = sequence_logprob(ref,    ci, cm).detach()  # log π_ref(y_好|x)
ref_rejected = sequence_logprob(ref,    ri, rm).detach()  # log π_ref(y_坏|x)
                                              ↑ .detach() 切断 ref 的梯度

# 3. 算 DPO loss
logits_diff = BETA * (
    (lp_chosen - lp_rejected) -          # policy 内部 chosen-rejected 差距
    (ref_chosen - ref_rejected)          # reference 内部 chosen-rejected 差距
)
loss = -logits_diff.log_sigmoid().mean()   # 鼓励 logits_diff 变大

关键点

  • detach():ref 是冻结的,梯度不能流过去
  • BETA:控制"拉多狠",0.1 是常用值
  • log_sigmoid:数值稳定的 −log σ(x) 计算
13 / 21

β 怎么选:超参里最重要的一个

β ↔ 隐式 KL 强度 ↔ 偏离 reference 的容忍度

β 的作用

logits_diff = β × (policy 内部差 − ref 内部差)

β 越大,loss 对差值越敏感,policy 被推得越远。

不同 β 的效果

β 值训练强度policy 偏离 ref语言能力偏好准确度
0.05温和很小几乎不变信号弱
0.1平衡适度微降够用
0.3激进较大下降强
1.0过激远可能崩过拟合风险

实战建议

• 从 β=0.1 起步,看 val loss 走势

• 如果偏好准确率上不去,小步往上加 (0.1 → 0.15 → 0.2)

• 如果 PPL 飙升超过 20%,调小 β 或减少训练步数

• 监控:val PPL + chosen/rejected 准确率 一起看

GRPO:推理模型的新范式

Group Relative Policy Optimization,DeepSeek R1 (2024)

核心思想

不需要 critic,直接对同 prompt 的一组回答做"组内相对比较"。

训练流程

prompt → policy 采样 K 个回答 → 规则/RM 给每个打分 → 计算组内 μ, σ,优势 Ai=(ri−μ)/σ → PPO-style clip loss + Ai

为什么适合推理模型

✅ 可验证奖励

数学题:答对 +1,答错 −1
代码:测试通过 +1,失败 −1

✅ 节省 critic

组内统计量自动当 baseline
省一半内存,训练更稳

✅ 长 CoT 友好

多次采样可探索不同解法
学"哪条思路更可能答对"

⚠️ 前提

必须有可验证的奖励信号
否则只能退回 DPO

PRM vs ORM:过程奖励 vs 结果奖励

给"中间步骤"打分 vs 只给"最终答案"打分

ORM (Outcome Reward Model)

只看最终答案对不对:

"42" → 答对 +1, 答错 −1

信号稀疏、长 CoT 难以训练。

PRM (Process Reward Model)

对推理的每一步打分:

step 1: 设未知数为 x → +0.3

step 2: 列方程 2x+3=7 → +0.5

step 3: 算出 x=2 → +1.0

信号密集、CoT 训练好,但标注贵。

对比

ORMPRM
奖励位置最后一步每一步
信号密度稀疏密集
标注成本低高(每步都要评)
适用短答案长 CoT / 推理
代表DeepSeek R1 早期OpenAI o1

在线 vs 离线:训练范式

偏好对是预先收集的,还是训练中边采边评?

离线 (Offline)在线 (Online)
数据来源预收集的偏好对训练中 policy 实时采样
代表方法DPO, IPO, KTO, SimPO, ORPOPPO, GRPO, Online DPO, RLOO
稳定性高中
实现复杂度低高
探索能力受限于固定数据强
内存小大(要存采样)

Online DPO 是个聪明的折中

每个 step:policy 采样 → RM 打分 → 构造新 (chosen, rejected) 对 → 跑 DPO loss

既有 DPO 的简洁,又有在线探索的强能力。LLaMA 3 / Qwen 2 大量使用。

实战选型:决策树

一个流程图解决"我该用啥"

你的任务是什么? │ ├── 通用对话模型 │ └── 偏好数据质量高? │ ├── 高 → SFT → DPO / SimPO / ORPO │ └── 一般 → SFT → IPO │ ├── 推理 / 数学 / 代码 │ └── 有可验证奖励? │ ├── 有 → SFT → GRPO (推荐) 或 RLOO │ └── 无 → SFT → DPO │ ├── 安全对齐 (避免有害输出) │ └── SFT → RLHF (PPO) 或 DPO │ └── 资源紧张 / 内存小 └── SimPO 或 KTO (省内存省数据)

决策三要素

① 任务:通用对话?推理?安全?

② 可验证性:答对/答错能自动判吗?

③ 资源:显存?数据量?

不确定时,默认从 SFT → DPO 起步,β=0.1,几千步看 val loss 趋势。

本课要点 + 思考题

回顾 + 课后练习

本课要点回顾

  • RL 想让模型 "更想说"好答案、"更不想说"坏答案
  • PPO 是基线,但要 RM + ref + critic,工程复杂
  • DPO 用解析式把 reward 写成 π/πref,砍掉了 RM
  • DPO 家族都在砍东西:ref → 单条数据 → 合并 SFT
  • GRPO 用"组内相对打分"替代 critic,适合可验证任务
  • 选方法看三件事:任务、可验证性、资源

思考题

1. 如果你只有 1 万条单条标注(无成对),但有 RM,你会怎么组合?

提示:KTO + Online DPO 各能解决什么?

2. DPO 训完后 PPL 飙升,怎么排查和修复?

提示:从数据、β、步数、ref 一一排查

3. 为什么 GRPO 在创造性写作上效果通常不如 DPO?

提示:创造性写作没有"标准答案",奖励信号稀疏
