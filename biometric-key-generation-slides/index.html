为什么 BKG 重要？

传统密码学密钥靠"记住"或"存住"，生物特征密钥靠"长在身上"——但生物特征 有噪声、隐私敏感、终生不变。这三大特性是 BKG 所有技术挑战的根源。

2.1 BKG 三大目标（ISO/IEC 24745 标准）

① 稳定性 Reproducibility

同用户多次生物采集 → 同一密钥

挑战：传感器噪声、姿态变化、年龄、表情...

解决：纠错码（BCH、RS、Polar） + Secure Sketch

② 安全性 Security

模板不可逆、不可链接、抗攻击

挑战：Inversion / Linkability / Replay 攻击

解决：不可逆变换 + 多因子 + Challenge-Response

③ 可撤销 Revocability

泄露后换 token 重新生成

挑战：泄露后无法恢复原生物特征

解决：Cancelable Biometrics + BioHashing

核心矛盾

稳定性需要"匹配"原始生物特征 → 安全性需要"不暴露"原始生物特征 → 这两个目标天然冲突。

这正是 2023-2026 整个研究领域的核心张力：如何在保证稳定性的同时保护生物特征隐私？

方向 ② 神经 FE (2/2) — 训练目标

核心 loss: 重建 + 隐私 + 一致性

L_total = α · L_recon  +  β · L_privacy  +  γ · L_consistency

L_recon       = E[ ‖D(S(E(x)), E(x')) - z‖² ]      ← 鲁棒性 (x,x' 同人)
L_privacy     = I(helper; x)  ≈ Rényi 散度上界     ← 不可逆
L_consistency = E[ ‖E(x) - E(x')‖² ]   当 x,x' 同人  ← 紧凑性

理论保证

信息瓶颈 (IB) 框架: min I(z; x) - λ·I(z; y),其中 y 是身份标签。最小化 z 对原始 x 的依赖,最大化对身份的依赖 —— 自动学到"身份必要信息"。

2026 落地关键

  • Rényi Differential Privacy (RDP) 比纯 DP 给出更紧的隐私预算
  • 训练用 DP-SGD,ε ≤ 1 已可商用 (Apple 在生产环境用)
  • Inference 阶段可走 TEE,完全消除 helper 泄露风险

代表工作

WiFaKey (2024) 是这条路的开山,但仅 face;BioDeepHash (2024) 加入了 hash 约束;2026 期待多模态 + IB 联合训练。

三方架构

Alice (发送方)

输入: 密钥 K + 生物特征 x

输出: 密文 c = E_θ(K, x)

目标: Eve 不能从 c 推出 K

Bob (接收方)

输入: c + 自己的生物特征 x'

输出: K' = D_φ(c, x')

目标: x = x' (同人) 时 K' = K

Eve (窃听方)

输入: c (无 x)

输出: K_hat = W_ψ(c)

目标: 猜 K(攻击者目标)

方向 ⑦ 神经密码学 (2/2) — 训练动态

Loss 矩阵

L_Alice  = -L_Bob + α · L_Alice_privacy
L_Bob    = E[ loss(K, K') | x = x' ]  +  E[ loss(K, K') | x ≠ x' 足够大 ]
L_Eve    = -E[ loss(K, K_hat) ]     ← 最小化 Eve 误判

训练顺序:  Alice + Bob 联合训练 5 步 → Eve 训练 1 步 → 循环

为什么 2026 这条路重新火？

  • · 2016 时代 NN 容量小,Alice 只能学会 XOR-like 协议
  • · Transformer + 大规模训练让 Alice 能学到"非平凡协议"
  • · Diffusion + flow model 让 Eve 也有强先验,逼 Alice 必须更聪明

形式化难点(可发论文的点)

· 可证明安全 = 学习到的协议能否等价为某已知 IND-CPA 安全协议? · 抗侧信道 = Eve 还能拿到中间激活,如何阻止? · 生物特征非完美匹配 = Bob 的 x' 与 Alice 的 x 永远有 5-10% 噪声

一个 agent loop

for round in 1..N:
    1. observe = agent.call_mcp("get_system_state")
    2. hypothesis = LLM(observe, attack_taxonomy)  # 猜哪里有漏洞
    3. payload = LLM.generate(hypothesis)           # 生成 attack 输入
    4. result = system.test(payload)                # 真实测试
    5. if success:                                  # 找到漏洞
        report = LLM.summarize(result)
        alert_human(report)
        add_to_attack_library(payload)
    6. else:
        learn_from_failure(observation)

14.18 训练目标(信息瓶颈 + DP)

Loss 设计

# 3 个对抗目标
L_recon = E[ ||z - D_θ(S_φ(z), z')||² ]   # 重建
L_privacy = -I(z; x_orig)                  # 互信息最小(用 MINE 估计)
L_consistency = E[ -log p(y | z) ]          # 身份分类(用 y = identity 标签)

# 总 loss
L_total = α·L_recon + β·L_privacy + γ·L_consistency

# DP 约束(每个 step 的梯度加噪声)
g = clip(∇L, C) + N(0, σ²I)  # 满足 (ε, δ)-DP
ε_total ≤ 1  # 用 RDP accountant 累加

为什么这套目标 work

  • · L_recon: 保证 z 和 z' 重建一致 → 鲁棒性
  • · L_privacy: I(z; x) 小 → helper 几乎不含 x 信息
  • · L_consistency: z 含身份信息 → 熵不丢
  • · DP 噪声: 理论保证 ε 累积,工程上 σ 通过 RDP accountant 自动选

理论下界(可证明)

由 IB 理论: H(K) ≥ I(z; y) - ε·D_KL 后,目标 GMR ≥ 1 - e-λ(I(z;y) - C_privacy)

14.20 风险点 & 落地路径

🔴 3 个高风险点(发论文时必被审稿人问)

  1. 熵估计无 ground truth
