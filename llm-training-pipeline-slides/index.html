类型来源典型规模特点

书籍Books3 / Project Gutenberg / 内部百 G质量高,长文
代码GitHub / The Stack数百 G需 license 过滤
论文arXiv / S2ORC / PubMed百 G高质量专业知识

采集要点

  • 多语言平衡:中英欧亚等多语种配比,避免英语霸权

经验值:训练 token 数 ≈ 模型参数 × 20。70B 模型至少要训 1.4T token,实际常 10-30 倍。

阶段 1 · 清洗、去重、过滤

从 100T 原始网页到 10T 高质量 token

处理流水线

原始网页 → HTML 解析 → 语言识别 → 规则清洗 → 去重 → 质量打分 → PII 脱敏 → token 流

关键环节详解

环节做法剔除率
规则清洗去 HTML/导航/页脚、长度过滤、符号比~40%
语言识别fastText/langid 多语言打分~20%
精确去重段落级 SHA-256 hash~10%
模糊去重MinHash LSH (Jaccard > 0.8)~15%
质量打分KenLM 困惑度 / 小模型分类器~30%
PII 脱敏正则 + NER 替换为 <EMAIL> 等~2%

质量过滤的两条路线

启发式 (快)

• 文档长度、词数、句子数
• 标点/字母/中文比
• 停用词比例、重复行比例
• 用 KenLM 算 perplexity,过滤异常值

模型打分 (准)

• 训一个小分类器(质量好/中/差)
• 用 GPT-4 当"教师"给数据打分
• 保留 top-K,扔掉 bottom-K
• 成本:几十万到几百万美元

阶段 1 · Tokenization 选型

把文本切成 token,直接影响训练效率和模型能力

主流方案对比

方案代表词表压缩率多语言工具
BPEGPT-2/3/450K-100K~4 chars/tok差tiktoken
SentencePiece BPELLaMA / Qwen32K-128K~3.5中sentencepiece
Unigram LMXLNet / ALBERT32K~3.8中sentencepiece
BBPEGPT-4o / Qwen2200K+~5好tiktoken

选型要点

  • 词表大小:越大 → 单 token 信息量高 → 序列短;但 embedding 表大,稀疏训练
  • 压缩率:越高越好,训练效率高(同样算力看更多文本)
  • 多语言:中英欧都要好,避免中文被切成 3 字节
  • 数字处理:每个数字 1 token 还是每位 1 token?影响算术能力
  • 特殊 token:<|endoftext|>、<|user|>、<|tool_call|> 等要预留

数字的 tokenization 是个大学问:Qwen2 把每个数字单独 1 token,显著提升算术能力。

阶段 1 · 数据配比与课程学习

不同来源数据怎么混,顺序怎么排

典型配比(以中文 LLM 为例)

类型占比说明
网页50-70%主菜,量大但杂
书籍/论文10-15%高质量长文,提升推理
代码10-20%逻辑和结构化能力
百科5-10%事实性
问答/对话5-10%对话格式

课程学习 (Curriculum Learning)

  • 简单 → 复杂:先喂短文、易懂文,后喂长文、专业文
  • 质量 → 多样:前 50% 用高质量,后 50% 引入多样
  • 数据采样不均匀:按"信息量"加权,信息量低的样本少采

退火 (Annealing) 阶段

预训练最后 5-10% 步,切换到高质量小数据(教科书、精选问答),在 LR 衰减配合下大幅提升能力。
这是 LLaMA 3 公开强调的 trick,被多家复现验证。

阶段 2 · 分布式训练:3D 并行

单卡放不下,只能拆开

3 种并行策略

策略拆什么通信开销典型规模
DP (Data Parallel)数据切成 N 份,每卡跑一份梯度 all-reduce8-256 卡
TP (Tensor Parallel)把一个矩阵乘拆到 N 张卡all-reduce 每层8-16 卡/节点
PP (Pipeline Parallel)把 N 层拆到 N 张卡点对点 send/recv跨节点 8-64

补充策略

  • SP (Sequence Parallel):长序列时切 seq 维,降低 TP 通信
  • EP (Expert Parallel):MoE 专用,把不同 expert 放不同卡
  • CP (Context Parallel):超长序列跨卡拆分 attention
  • ZeRO / FSDP:把优化器状态/梯度/参数切片,内存省 N 倍

真实训练配置示例(LLaMA-3 405B)

# 16384 GPU (H100) 训练 ~30 天
TP=8  PP=16  CP=2  ZeRO-1 (FSDP on data parallel rank)
# 总: 8 × 16 × 2 = 256 路并行组,每组 64 卡
# 配合 BF16 训练 + FP8 部分层

坑:TP 跨节点性能差(NVLink 才高效),一般 TP≤8 限制在一个节点内。PP 气泡率大,通常和 TP/DP 组合使用。

阶段 2 · 混合精度与数值格式

用更少的 bit 算更多的 token

精度格式

格式bits动态范围用途
FP3232±3.4e38优化器状态、loss
BF1616±3.4e38 (8 位指数)前向、反向、参数
FP1616±6.5e4 (易溢出)需 loss scaling,逐渐被 BF16 替代
FP8 (E4M3 / E5M2)8±448 / ±57344H100 时代新标准,加速 ~2x
FP44极小B200 / RTX 5090 实验中

典型混合精度策略

# 主流: BF16 主路径 + FP32 优化器状态 (AdamW)
with torch.autocast(dtype=torch.bfloat16):
    loss = model(input_ids, labels=input_ids)
loss.backward()        # BF16 梯度
optimizer.step()   # optimizer 内部用 FP32 master weight 更新

数值稳定性保障

  • Grad Norm 监控:训练中每步 log grad norm,异常时回滚
  • Loss spike 检测:loss 突然涨 > 2x,自动 skip 当前 step 或回 checkpoint
  • Q / K 矩阵的 attention logit 上限截断(防止 softmax 溢出)
  • BF16 > FP16:BF16 指数位宽,几乎不溢出,推荐优先用

阶段 2 · 优化器与学习率调度

SGD 早就过时,AdamW 是底座,分布式版是新前沿

主流优化器

优化器特点代表项目
AdamWAdam + 解耦 weight decay,行业标准几乎所有 LLM
Lion只用 sign(momentum),省显存BLOOM 等小模型
分布式 Adam / ZeRO-Adam把 Adam 状态切到多卡FSDP / DeepSpeed
分布式 Muon (2024)对参数矩阵正交化,显著加速Kimi K2 / NanoGPT speedrun
Adafactor用低秩近似二阶矩,省显存T5 / PaLM 早期

学习率调度

WSD (Warmup-Stable-Decay)

• 0~1% 步:线性 warmup
• 1%~90% 步:常数 LR
• 90%~100% 步:余弦/线性 decay 到 10%

优势:支持训练中途重启,工业界主流

Cosine Schedule

• warmup 后余弦降到 ~10% LR
• 平滑,损失曲线稳定
• 缺点:不支持续训,换 LR schedule 等于从头训

阶段 2 · 训练稳定性

训练崩溃的 5 大原因 + 应对

常见症状与处理

症状原因处理
Loss spike(突然涨)数据噪声 / LR 太大 / batch 异常skip 当前 step,记录,继续训
Loss → NaN溢出 / 除零 / 极差 batch立即 rollback,降 LR 50%
Loss 不下降数据配比错 / 架构 bug / LR 不对小实验快速验证,别死磕
模型不收敛初始化 / Norm 配置 / 数据有问题先 1/100 数据 + 1/10 模型过拟合验证
Eval 突然崩checkpoint 损坏 / OOM 写入失败保留最近 N 份,跨节点冗余存储

工程保险措施

  • 梯度裁剪:L2 norm 限制在 1.0,这是基本盘
  • Loss spike 自动跳过:超过移动平均 N 倍就 skip
  • 定期保存:每 1-2 小时存一份,保留最近 3-5 份
  • 异步 checkpoint:写入不阻塞训练(GCS / S3)
  • 数据校验:离线先做 1 epoch dry-run,统计 token 数 / batch 形状
  • 健康检查:监控 GPU 温度、NVLink 错误、磁盘 IO 延迟

真实代价:一次 NaN 没及时处理,可能浪费 1 周 GPU 时 + 几十万人民币。监控系统必须 7×24 有响应。

数据构造

来源特点成本

关键 trick

Loss Mask

• 只在 assistant 回复上算 loss
• 用户输入部分 mask 掉
• 用 -100 (PyTorch ignore_index)

Sequence Packing

• 把多条短样本拼到 max_len
• 用 attention mask 隔开
• 训练吞吐提升 3-10 倍

多轮对话

• 用 chat template 拼接
• 只在最后一轮 assistant 上算 loss
• 工具调用 / Function Call 模板

NEFTune

• embedding 加均匀噪声
• 免费 trick,显著提升指令遵循
• α=5 常用

阶段 5 · 对齐 (Alignment)

让模型"更愿意"说好的,"更不敢"说坏的

主流路径

SFT 完 → 选对齐方法 → DPO / SimPO / GRPO → 安全 RL → 评估

选型速查

场景推荐原因
通用对话DPO / SimPO简洁稳定,数据要求低
推理 / 数学 / 代码GRPO用规则奖励,能学"答对"模式
安全对齐PPO 或 DPO需要严格 KL 约束
创意写作DPO + Constitutional AI奖励信号稀疏,不能上 GRPO
资源紧SimPO / KTO省显存省数据

对齐的代价

对齐通常会让 PPL 上升(语言建模能力略降),因为 policy 偏离了 reference。
监控 eval PPL + 偏好准确率 + 任务榜单 三个数一起看,任意一个崩了就该停。

阶段 7 · Checkpoint 管理

模型有了,怎么存怎么用

保存策略

策略频率保留数用途
每 N 步存每 1-2 小时最近 3-5 份断点续训
退火后存关键里程碑长期保留主模型
外部存实时1 份主 + 1 份冷备防集群事故

格式

训练格式 (Framework Native)

• PyTorch: .pt / .bin
• DeepSpeed: ZeRO 分片,需 gather
• Megatron: TP/PP 切分,需转换
• 一般包含 optimizer state + model state

推理格式 (Deploy Ready)

• safetensors: HuggingFace 标准,无 pickle 风险
• GGUF: llama.cpp 量化格式
• TensorRT-LLM: NVIDIA 优化引擎
• AWQ / GPTQ: 4bit 量化

容错机制

  • 异步上传:checkpoint 写本地,后台 sync 到 S3/GCS,训练不阻塞
  • 校验和:每个 checkpoint 配 SHA256,定期验证完整性
  • 节点故障恢复:PyTorch Elastic / Slurm restart from ckpt
  • 模型分片:70B 模型 140GB,分布式保存避免单点失败

血的教训:没存够 checkpoint,集群故障一次丢几周训练。规则:再贵的存储也比 GPU 时便宜。

1数据里有重复(测试集泄漏到训练集)榜单虚高严格去重 + holdout 防污染

4LR schedule 中途换训练损失曲线断崖用 WSD 支持重启
5ZeRO-3 + TP 一起开通信爆炸,慢 5xZeRO-1 + TP+PP 更稳
6checkpoint 只存本地集群故障丢模型异步同步到对象存储
7对齐后没测 PPL语言能力掉了一大截同时监控 PPL + 偏好 + 任务榜

一页纸总结 + 思考题

回到流程,把握节奏

本课要点

  • 数据决定上限:采集 → 清洗 → 去重 → 过滤 → 配比 → 退火
  • 预训练是算力怪兽:3D 并行 + 混合精度 + 严格监控,容错第一
  • 中间训练是"调优期":长上下文、垂域、退火三个常见目标
  • SFT关键在数据质量 + loss mask + packing,数据量级反而不大
  • 对齐选型看任务:通用 DPO、推理 GRPO、紧资源 SimPO/KTO
  • 评估三层:榜单 + 内部 + 人工(LLM-as-judge 兜底)
  • 部署从 demo 到生产差 10 个工程问题:弹性、路由、缓存、安全、SLO

思考题

1. 你的项目数据有 5% 测试集泄漏到训练集,怎么排查?有什么自动检测方法?

2. 训练到一半,eval loss 突然涨了 30%,但 train loss 继续降,你怎么判断和应对?

3. 你的服务 QPS 涨 10 倍,推理成本线性涨,怎么用工程手段降到 3x?
