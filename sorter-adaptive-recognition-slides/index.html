1. 背景：现场条件持续变化，YOLO 需要"会适应"

现有 AI 模块以 YOLO 为主，完成目标检测、缺陷识别、类别判定和喷阀分选控制。部署后，物料和成像条件会持续变化：

环境与设备漂移

  • 光线 / 天气 / 温湿度变化
  • 相机曝光、镜头污染、光源衰减
  • 传送带速度、振动、触发抖动

物料与缺陷漂移

  • 农产品批次、成熟度、含水量、表皮颜色
  • 珠宝材质、透明度、切面、高光、反射
  • 缺陷形态轻微漂移，新缺陷偶发
问题：现场不能频繁人工重训，但模型要持续准确 → 需要一套"不重训也能自适应"的体系。

2. 设计目标与核心原则

四个目标

  1. 主模型训练完成后，现场主要执行 TTA / CTTA，尽量不频繁重训 YOLO
  2. 增加记忆能力：特征、类别原型、批次状态、困难样本、人工纠错
  3. 保证工业稳定性的前提下，越用越懂现场
  4. 支持周期性 数据蒸馏 + 模型升级，将现场经验沉淀回模型版本

核心原则

主模型保持稳定 → 在线层轻量自适应 → 记忆库积累经验 → 蒸馏升级闭环进化

把"会变"的部分（阈值、统计量、adapter、prototype）和"不变"的部分（YOLO 主干）解耦，让变化被吸收而不污染主模型。

3.1 模块命名建议：ARE · Adaptive Recognition Engine

① Domain Monitor

环境与批次状态监控：亮度、清晰度、颜色分布、置信度漂移、未知率、冲突率。

② Base Detector

YOLO 主识别模型（检测 + 初步分类），输出 bbox、conf、embedding、quality、domain_state。

③ Online Adapter

测试时自适应模块：动态阈值、BN/校准层、温度、per-class bias、轻量 adapter。

④ Prototype Memory

类别原型记忆库：短期批次 + 长期跨批次原型 + 异常/困难样本。

⑤ Hard Sample Buffer

困难样本池：低置信、冲突、误剔、漏剔、未知样本。优先用于人工复核和蒸馏。

⑥ Distillation Updater

周期性蒸馏升级器：服务侧执行，把现场经验沉淀回轻量 YOLO Student，灰度发布。

命名既覆盖"监控 → 检测 → 自适应 → 记忆 → 决策 → 升级"完整闭环，也方便和客户沟通方案模块边界。

4. 模型分层：YOLO 主模型负责"稳"

主模型负责稳定、实时的检测和初步分类，建议按场景选择路线：

主检测器选型

  • 农产品缺陷识别：YOLOv8 YOLOv10 YOLO11 YOLO12
  • 小缺陷 / 微小异物：YOLO + 高分辨率 ROI 分类器
  • 珠宝识别：YOLO 检测定位 + ROI 多分支分类器
  • 新品类 / 开放类别辅助：YOLO-World / Grounding DINO 作辅助，不直接控制喷阀

推荐输出字段（不只是 bbox + class）

bbox class_id confidence object_feature color_feature texture_feature shape_feature quality_score domain_state

object_feature 用于记忆库检索；domain_state 触发在线自适应。

4.1 ROI 特征模型：多模态 embedding

对每个 YOLO 检出的目标裁剪 ROI，再提取 embedding。建议同时输出多模态特征：

Encoder 选型

  • 直接复用 YOLO backbone/neck 中间特征（零成本）
  • 增加一个轻量 ROI encoder（专用）
  • 珠宝等复杂纹理：metric learning encoder
  • 研发期可用 DINOv2 / CLIP / SigLIP，线上蒸馏成轻量 encoder

特征字段

embedding 256/512 维 HSV / Lab 直方图 texture 描述子 shape 描述子 area / 长宽比 / 圆度 局部缺陷热图摘要

embedding 提供语义相似度，颜色/纹理/形状提供可解释判据，方便客户验收和回溯。

5. Test-Time Adaptation：四级体系，按风险逐步升级

现场不重训 YOLO 主干，只更新统计量、阈值、校准层、adapter、prototype，所有更新必须可回滚。

等级名称更新什么不更新 / 保护
L0 无权重自适应（第一阶段优先落地） 自动曝光 / 白平衡；亮度 / 清晰度质量；当前批次颜色 / 置信度分布；动态阈值；记忆库检索 + 分数融合校准 任何模型参数。风险最低，适合先上线。
L1 归一化统计 + 校准参数 BN running mean / var；分类头 temperature；per-class bias；confidence calibration；小型 adapter YOLO backbone / neck 大量卷积 / 检测头全部参数。
L2 Teacher-Student 在线自适应 Teacher（EMA）生成稳定伪标签；Student 轻量更新 adapter / BN / calibration；Memory 修正伪标签质量 必须加：强弱增强一致性、高置信筛选、参数回滚、原始模型锚定。
L3 离线周期再训练 / 蒸馏（非实时） 高置信 + 困难 + 人工纠错 + 新批次代表样本 → Teacher/Foundation 辅助标注 → 蒸馏训练轻量 YOLO Student → 灰度发布 在服务侧 / 维护侧执行，不在产线实时跑。

6. 记忆库设计：三层记忆各司其职

🕐 短期：当前批次记忆

保存最近几分钟到几小时的高置信样本。

  • 当前正常物料颜色 / 大小 / 纹理分布
  • 调整类别阈值
  • 识别短期环境变化

字段：material_id / class_id / feature_center / color_center / texture_center / shape_stats / confidence_mean / sample_count / time_window / camera_state

📚 长期：跨批次类别原型库

历史稳定出现过的类别原型。

  • 辅助判断 YOLO 低置信结果
  • 识别历史上见过的物料变体
  • 支持客户个性化经验积累
  • 为后续蒸馏提供代表样本

字段：prototype_id / class_id / feature_vector / color_hist / texture / shape / camera_condition / sample_count / trust_score / last_update / last_used / source

⚠ 异常：困难样本池

不直接参与在线自动学习。

  • 低置信 / 多类分数接近
  • YOLO 与记忆库判断冲突
  • 时序结果不一致
  • 人工纠错 / 误剔 / 漏剔
  • 新物料 / 未知缺陷

优先用于人工复核和后续蒸馏训练。

6.1 记忆库更新门控：避免"越学越错"

高置信门控

只有全部满足才进入自动记忆：

YOLO conf > T_class prototype sim > S_class image quality > Q_min domain shift < D_max recent conflict < C_max

多帧一致性 + 类别平衡

  • 连续窗口内类别分布稳定才允许批量更新
  • 每类最多 K 个原型，每批最多写入 N 个原型
  • 相似原型合并；罕见但人工确认的原型保留

可信度排序

人工确认样本 > 多模型一致高置信 > 单模型高置信 > 记忆库推断

客户反馈样本不能被自动记忆覆盖；异常批次统计不直接污染长期原型库。

7. 推理流程：12 步端到端

1. 图像质量 → 2. YOLO 检测 → 3. 裁剪 ROI → 4. 提取多模态特征 → 5. 查短期记忆 → 6. 查长期原型 → 7. domain shift → 8. 动态阈值 → 9. 分数融合 → 10. 决策 → 11. 高置信入记忆 → 12. 冲突入困难池

初期：可解释线性融合

final_score =
  0.60 × yolo_score
  + 0.20 × long_memory_similarity
  + 0.10 × short_batch_similarity
  + 0.05 × class_prior_score
  + 0.05 × image_quality_correction

后期：小 meta-classifier

输入：yolo_score、top2 gap、prototype_sim、batch_sim、image_quality、domain_shift、object_size、color_distance、texture_distance

输出：calibrated class probability + reject/accept 决策

初期用线性融合便于客户验收和调试；样本积累后切换到 meta-classifier 提升边界样本精度。

8. 自适应触发：不是每帧都更新

Domain Monitor 持续输出 9 个漂移指标，按强度触发不同动作：

监控指标

  • brightness_shift
  • color_temperature_shift
  • blur_score
  • background_shift
  • object_color_distribution_shift
  • class_confidence_distribution_shift
  • prototype_distance_shift
  • unknown_rate
  • conflict_rate

触发规则

  • 轻微变化：只更新短期统计 + 阈值（L0）
  • 持续变化：更新 BN / adapter / calibration（L1）
  • 明显异常：暂停在线学习，进入保守模式
  • 未知物料：启用开放词汇辅助模型 + 人工确认

运行模式

Normal Mode 正常模式 Adaptive Mode 自适应模式 Conservative Mode 保守模式 Review Mode 人工复核 Rollback Mode 回滚

9. 防漂移与安全机制：工业设备优先稳定

8 条工业级保护

  1. 原始模型锚定：保留 base model 副本
  2. 参数白名单：只允许 BN / adapter / temperature / bias / prototype
  3. 更新限幅：每次更新幅度不能超过阈值
  4. 回滚机制：误剔率 / 低置信率 / 冲突率异常时回滚
  5. 影子评估：在线更新模型先作 shadow 运行
  6. 记忆库版本化：每次写入可恢复
  7. 人工确认优先：客户反馈不被自动记忆覆盖
  8. 异常批次隔离：不直接污染长期原型库

5 种运行模式

模式适用场景
Normal现场条件稳定，按基线推理
Adaptive检测到漂移，启动 L0/L1 自适应
Conservative明显异常，保守推理 + 上报
Review触发人工复核，困难样本进队列
Rollback关键指标异常，秒级回滚到 base

10. 农产品 vs 珠宝：差异化策略

🌾 农产品

主要变化：

  • 批次颜色差异
  • 成熟度、含水量
  • 表皮纹理
  • 霉变、破损、虫蛀、黑点
  • 小异物、杂质

适配重点：

  • 强依赖颜色 / 纹理特征
  • 短期记忆快速适应当前批次
  • 困难样本主要是小缺陷 + 杂质

💎 珠宝

主要变化：

  • 材质（钻石 / 彩宝 / 贵金属）
  • 透明度、切面、折射
  • 高光、镜面反射、阴影
  • 镶嵌方式、姿态
  • 微小内含物、色级

适配重点：

  • 强依赖 shape / embedding 特征
  • ROI 多分支分类 + metric learning
  • 高光 / 反射需要曝光与白平衡更精细的 Domain Monitor

11. 总结：四条主线 + 一张图

① 主模型稳定

YOLO 现场不重训主干；版本管理 + 灰度发布。

② 在线层轻量

L0/L1 统计量 + 校准；L2 Teacher-Student；L3 离线蒸馏。

③ 记忆库分层

短期批次 + 长期原型 + 困难样本，严格门控与版本化。

④ 工业级保护

参数白名单 + 影子评估 + 5 种运行模式 + 异常回滚。

一句话：让 YOLO 主模型稳定，靠 在线层 + 记忆库 吸收现场变化，再把经验蒸馏回模型，形成可持续进化的闭环。

下一步建议：先落地 L0 + 短期记忆 + 长期原型库（风险最低、收益最快），再分阶段引入 L1/L2 和离线蒸馏。

Q & A

讨论题 ①：如果客户现场 GPU 资源有限，L0 + 记忆库 + L1 校准 是否足以覆盖 80% 的漂移？
讨论题 ②：困难样本池的"人工复核" 流程要不要做到实时？这会决定 ④ Decision Engine 的 SLA 设计。
讨论题 ③：蒸馏升级的触发条件——是按时间（每月/每季）还是按数据量（新增原型 / 困难样本达到 N）？
