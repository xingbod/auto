01

核心思想:从"两段式"到"端到端",从"单任务"到"6 任务统一"

END-TO-END · UNIFIED · NMS-FREE

以前 YOLO 推理后要跑 NMS (非极大值抑制) 去重, YOLO26 默认 one-to-one head, 输出直接是最终结果, 省掉后处理。

OLD 之前 YOLO (v8/v11)
  • Head: One-to-Many (Anchor + DFL)
  • 后处理: 必须 NMS 去重
  • 任务: 每个任务单独训一个模型
  • 代表: YOLOv8 / YOLO11 / YOLOv10
YOLO26 Ultralytics 2026
  • Head: One-to-One (默认) / O2M (切换)
  • 后处理: 无需 NMS (端到端)
  • 任务: 检测/分割/姿态/分类/OBB 统一
  • 代表: YOLO26 + YOLOE-26 (开放词汇)
⚙️ 推理流程对比
[旧]  图像 → Backbone → Neck → One-to-Many Head → NMS 去重 → 框
[YOLO26] 图像 → Backbone → Neck → One-to-One Head → 直接是最终框  (无 NMS)
02

4 大设计领域:YOLO26 的核心创新

FOUR DESIGN AREAS

Ultralytics 官方把 YOLO26 的改进归为 4 个方面, 一起构成"更准更快"的权衡:

1 端到端推理 END-TO-END ⚡
默认 one-to-one head, 预测直接是结果, 不需要 NMS。
部署简化 + 减少后处理延迟
2 轻量 box 回归 NO DFL 🪶
移除 DFL (Distribution Focal Loss), 检测头更简单, 保留无约束回归范围。
推理更快 / 部署更易
3 训练配方升级 RECIPE 🍳
MuSGD 优化 + Progressive Loss + STAL, 小目标监督更强。
收敛更稳 / 小物体更准
4 任务特定头 TASK HEADS 🎯
检测/分割/姿态/分类/OBB 各自专用头, 同一套主干 切换。
一模型多任务 / 训练流程统一
03

6 大任务:同一套模型,切换 head 即可

SIX TASKS · ONE BACKBONE

YOLO26 共享主干, 通过切换 head 覆盖主流视觉任务:

🔲 目标检测
框出图中所有目标位置 + 类别
通用 · 监控 · 自动驾驶
✂️ 实例分割
每个目标的像素级轮廓
医疗 · 抠图 · 缺陷检测
🗺️ 语义分割
逐像素分类 (不分个体)
自动驾驶 · 遥感
🧍 姿态估计
检测人体关键点 (17 点)
健身 · 动作捕捉
🏷️ 分类
整图类别判断 (无框)
质检 · 内容审核
🧭 OBB 旋转框
带角度的检测框
航拍 · 遥感 · 文档
One-to-Many (O2M) 高精度
输出多个候选, 需 NMS 去重, 精度高。
👉 适合: 离线推理 / 服务器端 / 精度优先
One-to-One (O2O) 端到端
输出直接是最终结果, 无需 NMS, 速度更快。
👉 适合: 边缘部署 / 实时 / 移动端

05

新手最常踩的 4 个坑

COMMON PITFALLS
✗
"YOLO26 = YOLOv8 改名" 👉 不是改名。是新一代: 端到端无 NMS + 移除 DFL + 新训练配方 + 6 任务统一。
✗
"默认 one-to-one 一定更好" 👉 O2O 速度快但精度略低。精度优先选 O2M + NMS, 速度优先选 O2O, 根据场景切换。
✗
"YOLO26 一上来就能用" 👉 依赖 Ultralytics 包 ≥ 8.4.76。旧版 ultralytics 没有 YOLO26 模型, pip install -U ultralytics。
✗
"模型越大越好" 👉 YOLO26x 比 n 慢 7 倍, 精度只高 16 mAP。边缘部署优先 n/s, 云端才用 l/x, 别盲选大模型。
