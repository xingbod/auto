两阶段 vs 单阶段: 速度换精度的取舍

YOLO 把"两阶段"打成了"单阶段"比赛

两阶段 (R-CNN 系列)

阶段 1: 提候选区 (region proposal)
阶段 2: 在候选区上做分类 + 精修

  • + 精度高 (2014-2018 一直是 SOTA)
  • + 适合复杂场景、小目标
  • − 慢 (R-CNN 47s, Fast R-CNN 0.3s/图)
  • − pipeline 复杂,难端到端训练

代表: R-CNN, Fast R-CNN, Faster R-CNN, Mask R-CNN

单阶段 (YOLO / SSD / RetinaNet)

一次前向 → 直接出所有 box + 类别

  • + 极快 (YOLO 45 FPS, SSD 59 FPS)
  • + pipeline 简单,工程化友好
  • + 端到端训练,易于迭代
  • − 早期精度不如两阶段 (v1: 63.4 mAP vs Faster R-CNN 78.8)
  • − 小目标 / 密集场景更弱

代表: YOLO 系列、SSD、RetinaNet、CenterNet、FCOS

YOLOv1 · 2015 · 单阶段开山之作

Joseph Redmon et al. · CVPR 2016 · "You Only Look Once: Unified, Real-Time Object Detection"

核心贡献

  • 把 detection 变成单个 CNN 的回归问题
  • 45 FPS (Titan X),相比 Faster R-CNN 提升 6×
  • 全局推理: 整张图一次卷积,可学到上下文
  • 泛化能力比 R-CNN 强 (在自然图像以外的领域)

作者 & 背景

Joseph Redmon (华盛顿大学),Santosh Divvala, Ross Girshick, Ali Farhadi

Redmon 后来做出了 Darknet,2018 后宣布退出 CV 圈,称"军用 AI 不该被研究"

架构: 24 conv + 2 FC

448×448×3→ 24 conv→ FC 4096→ 7×7×30

GoogLeNet 启发的 backbone,最后输出 S×S×(B×5+C) = 7×7×(2×5+20) = 7×7×30

局限

  • − 每个 cell 只 2 个 box,密集目标挤
  • − 难处理小目标、群体 (鸟群)
  • − 63.4 mAP,显著低于 Faster R-CNN 78.8
  • − 训练 loss 不区分大小 box 误差

YOLOv2 & YOLO9000 · 2017

"Better, Faster, Stronger" · CVPR 2017 · 引入 anchor + 多尺度

Better

  • 引入 anchor boxes (Faster R-CNN 风格)
  • BN 层所有 conv 之后
  • 高分辨率分类器 448 → 416
  • passthrough 层融合细粒度特征
  • multi-scale training (320-608 随机)

Faster

  • 新 backbone: Darknet-19 (19 conv)
  • 只用 5.58B 浮点 / 图
  • 比 VGG-16 快 6×

Stronger (YOLO9000)

  • 联合训练 检测 + 分类数据集
  • 检测: COCO 80 类,分类: ImageNet 9000 类
  • 层级分类: WordTree 合并 9418 类
  • 能识别 "Norfolk terrier" 这种细粒度
"我们提出 YOLO9000,一个能实时检测超过 9000 物体类别的模型,通过联合优化检测和分类实现。"
— Redmon & Farhadi, YOLO9000 论文, CVPR 2017

结果: 78.6 mAP (416 输入, 比 v1 涨 15 个点) · 67 FPS · 仍比 Faster R-CNN 快

YOLOv3 · 2018 · 工业分水岭

Redmon & Farhadi · arXiv:1804.02767 · 多尺度 FPN · 工程化转折点

三大关键升级

Darknet-53→ FPN 3 尺度→ logistic 分类
  • Darknet-53: 53 层 + 残差连接,精度追平 ResNet-152,速度快 2×
  • 多尺度预测: 3 个尺度 (13×13, 26×26, 52×52) 检测不同大小目标
  • logistic 分类: 独立 logstic 而非 softmax,可支持多标签 (一个女人 + 一个人)

数据

  • COCO mAP-50: 76.5 (vs v2 的 76.8 几乎持平)
  • 但 mAP @0.5:0.95: 28.2 (vs v2 的 21.6 涨 7 个点)
  • 30 FPS @ 416,第一次"实时 + 准"二者兼得

架构总览

Backbone Darknet-53 (53 层残差)

Neck FPN (3 尺度横向连接)

Head 3 个独立检测头,每尺度 3 anchor

Loss MSE 回归 + binary cross-entropy 分类

意义

  • v3 是 工程界最常用的 YOLO,到 2022 还有大量项目在用
  • Darknet 框架使用率最高
  • 论文最后一次由 Redmon 主导 (后来他退出 CV 圈)

YOLOv4 · 2020 · "Bag of Freebies" 大集合

Alexey Bochkovskiy et al. · arXiv:2004.10934 · Redmon 退出后社区接力

核心方法论: 拆成两类 tricks

Bag of Freebies (BoF) — 训练阶段涨点

只改训练策略,不改推理开销的数据增强 + 正则化:
CutMix Mosaic MixUp DropBlock Label Smoothing CIoU Loss

Bag of Specials (BoS) — 推理阶段加小模块

增加少量推理开销但能涨点:
Mish 激活 CSP 模块 SPP PAN SAM 注意力

架构选择

CSPDarknet-53→ SPP→ PANet→ YOLOv3 head

数据

  • MS COCO: 43.5% AP @ 65 FPS (Tesla V100)
  • 比 YOLOv3 涨 10 个点 AP,推理速度还更快
  • 代码用 Darknet 框架 (非 PyTorch)

意义

  • 第一次系统性把"训练 trick"工程化总结成方法论
  • 带动后续 v5 / v6 / v7 全部沿用 "BoF + BoS" 思想
  • 作者 Bochkovskiy 是 Redmon 之外的接力者,延续 YOLO 命名

YOLOv5 · 2020 · PyTorch 化 + 工程化生态

Ultralytics · Glenn Jocher · 没有正式论文,GitHub 直接开源 · 1.5 万星只用 3 个月

关键决策: 重写 + 重塑

  • PyTorch 框架 (Darknet → PyTorch)
  • 5 个尺寸 (n/s/m/l/x) 一键切换,速度/精度 trade-off 标准化
  • Mosaic 4 图 增强默认开启
  • AutoAnchor 工具自动匹配数据 anchor
  • Ultralytics API: 一行 model.train() 开训

引发了 "YOLOv5 没有论文算不算学术工作" 的长期争议

YOLOv6 & YOLOv7 · 2022 · 工业 + 学术双轨

美团 v6 · 中研院 / Academia Sinica v7 · 同期发布,不同侧重

YOLOv6 (美团, 2022.06)

目标: 工业 GPU 部署优化

  • backbone: EfficientRep (重参数化 RepVGG 风格)
  • head: 解耦头 (Decoupled Head) + Anchor-free
  • loss: SIoU + VariFocal
  • 5 个尺寸 (n/t/s/m/l),V100 上 n 版 1234 FPS
  • 工业部署导向, 提供 TensorRT 量化工具链

arXiv:2209.02976 · 代码: meituan/YOLOv6

YOLOv7 (Academia Sinica, 2022.07)

目标: 精度极限 (SOTA 优先, 速度其次)

  • backbone: E-ELAN (扩展高效层聚合)
  • 复合缩放 (Compound Scaling) 用于检测头
  • 辅助头训练 + 标签重排 (planned re-parameterized conv)
  • 5-160 FPS 全段覆盖, COCO 56.8% AP @ 30 FPS
  • 比 v5/v6 都准, 但 PyTorch 实现重, 部署复杂

arXiv:2207.02696 · 代码: WongKinYiu/yolov7

"YOLOv7 在 5-160 FPS 范围内, 在速度和精度上都超过了当时所有已知检测器。"
— Chien-Yao Wang, Alexey Bochkovskiy, Hong-Yuan Mark Liao, YOLOv7 论文

v8 = "v5 + anchor-free + 多任务",沿用 n/s/m/l/x 5 尺寸

YOLOv9 · 2024 · 可编程梯度信息 PGI

Chien-Yao Wang et al. · arXiv:2402.13616 · 解决"深度网络信息瓶颈"

问题: 深度网络 = 信息丢失

网络越深,前向传播 + 监督损失梯度回传时,信息 (尤其是小目标) 会丢失

传统 skip / concat 都不够 → YOLOv9 提出 PGI

PGI: 可编程梯度信息

  • 主分支: 正常的前向 + 监督
  • 辅助可逆分支: PGI 把梯度信息"显式构造"再传回主分支
  • 可逆函数,推理时不需要 → 0 推理开销

GELAN: 轻量高效聚合

  • 基于 ELAN,梯度路径规划
  • 支持任意 block,比 v7 的 E-ELAN 更通用

YOLOv10 · 2024 · 真正的 NMS-Free

Ao Wang et al. (Tsinghua) · arXiv:2405.14458 · 一致性匹配 + 双头

问题: 为什么 YOLO 一定要 NMS?

传统 YOLO 一个目标会预测多个重叠 box,推理时需要 NMS 后处理

NMS → 不可微分 → 端到端部署困难 + 速度瓶颈

YOLOv10 解决方案: 一致性双头

一对一 (训练)

每个 gt 只匹配 1 个 prediction,无 NMS 训练

一对多 (辅助训练)

训练时多匹配,提供丰富监督

推理时 只保留一对一头 → NMS 取消

其他优化

  • Rank-guided block design 减少冗余 stage
  • 大核卷积 增强感受野
  • 自注意力 PSA 模块

YOLOv12 · 2025 · 注意力机制入侵 YOLO

核心: 让 YOLO 用 Attention

传统 YOLO = 纯 CNN,v12 = CNN backbone + 轻量 Attention 增强

三大组件

① Area Attention (A2)

② R-ELAN

Reparameterized ELAN,边缘聚合 + 缩放

③ 整体架构优化

减少堆叠层数,补偿 attention 算力

技术线 4: 标签分配 Label Assignment 演进

"哪个 anchor / 哪个 prediction 负责哪个 gt?"

关键问题

一张图有 N 个预测框,但 gt 只有 K 个 (K < N),需要决定每个 gt 由哪些预测负责

早期硬规则 → 现在软自适应

3 个里程碑

① 固定规则 (v1-v5)

用 IoU 阈值匹配: IoU > 0.5 算正样本,其余负样本。简单但缺灵活性

② ATSS / SimOTA (v6-v7)

ATSS: 自适应阈值,根据 anchor 统计 IoU 决定 · SimOTA: 用 Sinkhorn 求解最优分配,加 cost 矩阵

③ Task-Aligned Assigner (v8-v26)

把分类分数 + 定位质量 (IoU) 相乘做"对齐度",作为分配依据

演进意义

  • 标签分配 = 隐式学习率: 决定哪些预测被加速,哪些被抑制
  • 从"硬规则"到"软对齐" = 端到端可学
  • NMS-free 路线 (v10, v26) 的核心前提

TL;DR

标签分配这个"小问题",实际上是 YOLO 后面 5 代性能提升的隐形主推手

"Task-aligned assignment is a key component of the YOLOv8 performance gain."
— Ultralytics YOLOv8 文档, 2023

YOLO 系 vs DETR 系 · 同期对比

两条路线在 2024+ 合流

YOLO 系 (单阶段 + anchor)

  • 代表: v1-v26 + SSD + RetinaNet
  • 核心: 一次前向 + 回归
  • 优势: 快 (5-160 FPS) + 工程化好 + 部署生态成熟
  • 劣势: 早期需 NMS + anchor 调参
  • 2024+: NMS-free (v10, v26) 吸收 DETR 优点

DETR 系 (端到端 + 集合预测)

  • 代表: DETR (2020) → Deformable DETR (2021) → DINO (2022) → RT-DETR (2023)
  • 核心: 集合预测 + 二分匹配 + Transformer
  • 优势: 端到端 + NMS-free + 全局注意力
  • 劣势: 训练慢 (200 epoch+) + 算力大 + 早期不实时
  • 2024+: RT-DETR 拉到 100+ FPS, 实战可比 YOLO

合流趋势 (2024-2025)

① YOLO 吸收 Attention (v12) 和 NMS-free (v10, v26) ② DETR 吸收实时性 (RT-DETR) ③ 区别模糊化: 两个系列都在追"端到端 + 实时 + 注意力"

应用 + 局限 · 现实取舍

10 年 11 代,YOLO 已经成为 "目标检测" 事实标准

应用场景 (已被广泛使用)

🚗 自动驾驶

🏭 工业质检

缺陷检测 / 计数 / 定位

🏥 医疗影像

细胞 / 病灶 / 切片

📹 智能监控

人群计数 / 异常行为

病虫害 / 果实 / 无人机

🤖 机器人

抓取 / 导航 / 服务机器人

局限与挑战

  • 小目标: 远景 / 高分辨率图,精度仍弱 (STAL / PGI 是 v9-v26 主攻方向)
  • 遮挡: 严重遮挡下召回率显著下降
  • 极端尺度: 极大或极小目标并存时
  • 域迁移: 跨场景 (白天 → 夜晚) 性能下降
  • 数据效率: 相比半监督 / 自监督方法仍弱
  • 类别长尾: 长尾分布数据集精度差
  • 3D / 多模态: 纯 2D 视觉,接 LLM 还在早期

6 大主线 总结 YOLO 10 年

理解这 6 条主线,等于看完了 YOLO 史

① 单阶段路线胜利

从 "R-CNN 精 / YOLO 快" 二分, 到 2025 主流单阶段路线, YOLO 用 10 年证明了 "快 + 准" 可以兼得

② 实时性是 YOLO 的基因

v1 45 FPS, v8 93 FPS, v26 91 FPS · 实时不是目标, 是前提 · "You Only Look Once" 名字就是承诺

③ Anchor 从有到无 (v1→v8+)

v2-v7 靠 anchor · v8 全面 anchor-free · 减少超参 + 提升可学性 + 方便 NMS-free

④ NMS 从有到无 (v1→v10+)

v10 一致性双头开启 NMS-free · v26 进一步 DFL-free · 真正 "端到端"

⑤ 模块化 + 注意力融合

CSP → C2f → C3k2 → R-ELAN · v12 开始引入 Attention · v26 把 LLM 训练 trick (MuSGD) 移植到视觉

⑥ 工程化生态 + 多人接力

Redmon (v1-v3) → Bochkovskiy (v4) → Ultralytics (v5/v8/v11/v26) → 清华 / 中研院 / 美团 (v6-v12) · 从 1 人项目 → 跨公司开源生态 · GitHub 11 万星 · 30+ 部署平台
